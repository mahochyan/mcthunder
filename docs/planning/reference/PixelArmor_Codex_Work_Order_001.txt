二、本轮必须做出的可玩内容
A. 靶场与外观
- 一个平坦靶场，包括地面、围墙、几个可碰撞的箱子，以及三块静态靶板。
- 一辆原创方块低模坦克。至少能分辨车体、左右履带、炮塔和炮管；允许用 Godot 基础几何体和脚本搭建，不需要外部模型。
- 使用简洁、统一的颜色和清楚的光照，让地面、坦克与靶板容易分辨。本轮不要为了贴图或精细美术阻塞开发。

B. 驾驶
- W 前进，S 后退，A/D 让车体向左/右转；不允许左右平移，允许原地转向。
- 采用 CharacterBody3D 或同等简单、可控的方案，有加速、减速和倒车速度限制。先不做真实履带链、悬挂或刚体翻车。
- 初始调参建议：前进最高 8 米/秒，倒车最高 3 米/秒；所有速度和加速度集中配置。这些只是游戏初始参数，不是历史性能数据。
- 松开按键会逐渐停车；车辆不能穿地或穿墙。

C. 瞄准与相机
- 鼠标控制观察/瞄准方向，炮塔按有限转速追随目标，不瞬间旋转。初始炮塔转速可设为 35 度/秒，炮管俯仰范围可设为 -8 到 +20 度。
- 车体转向与炮塔瞄准分开，不因为按 A/D 就把观察方向强制甩回车头。
- 有第三人称跟随相机；按住鼠标右键进入简易炮镜，松开返回。
- 区分玩家想瞄的位置和炮管实际指向的位置；至少用两种简单标记表示。屏幕后方的投影标记应隐藏或限制，不能跳到错误位置。
- 第三人称相机有防穿墙处理，查询排除本车。炮镜位置避免被自身模型挡住。

D. 射击
- 鼠标左键开炮，每次射击后有 2 秒装填冷却；持续按住不能绕过冷却。
- 本轮允许用射线即时命中，不做弹道下坠、装甲穿透或模块损伤。
- 命中查询必须依据炮口实际方向，而不是直接使用相机射线代替武器命中；只处理第一处有效碰撞，排除本车。
- 相机看到目标但炮管被墙遮挡时，不得击中墙后的目标。炮管穿入墙体时也必须阻止穿墙开火，例如额外检查炮根到炮口之间的遮挡。
- 开炮时有简单炮管后坐、炮口闪光或短暂弹道线；这些效果不改变命中规则。命中靶板时靶板短暂变色，并增加该靶板的命中次数。
- 本轮不设置整车血条，也不冒充已经做出穿甲系统。

E. 基础界面与重置
- 显示速度、装填剩余时间、操作提示和靶板命中次数。
- 优先使用清楚的中文；如当前环境不能可靠显示中文，临时使用英文并提供中文操作说明，不随意下载或分发字体。
- R 重置坦克位置、运动状态、装填状态与靶板记录。
- Esc 暂停并释放鼠标；再次 Esc 或点击明确的“继续”按钮恢复。恢复游戏的点击不能意外开炮。
- 窗口失去焦点时自动暂停，避免切回后车辆仍在移动。

三、工程约束
1. 将 project.godot 放在当前项目根目录，设置好主场景和全部输入映射，不要求用户手工连接节点或复制代码。
2. 按职责拆分车辆运动、炮塔/相机、射击和界面；可以少量脚本实现，不把所有功能堆进一个巨大脚本，也不建设无关的通用框架。
3. 统一约定 1 单位约等于 1 米、Y 轴向上、车辆前方为 -Z；碰撞层、遮挡查询和自身排除集中说明。
4. 建立简短 AGENTS.md，保存本项目目标、技术栈、运行方式、测试方式和本单边界。
5. tools/godot 添加 .gdignore，并将引擎文件、.godot 缓存和备份目录从 Git 跟踪及游戏资源打包中排除。
6. 不安装第三方游戏插件，不接入外部 API，不实现网络对战、电脑敌人、内构穿甲、科技树、存档或更多车型。暂不导出独立 exe；先通过本机 Godot 运行验收。

四、必须实际自检
1. 使用本机 Godot 执行资源导入和脚本检查，再执行有限帧数、带超时的无窗口启动检查。先查看该版本的命令行帮助，保存实际命令、退出码以及标准输出/错误输出。
2. 不以退出码为唯一依据，同时检查解析错误、脚本异常和资源缺失。不要用删除功能、删除测试、吞异常或隐藏报错的方式伪装修复。
3. 至少建立并执行以下自动检查：主场景和必要节点能够加载；输入动作存在；连续射击受冷却限制；遮挡墙后的靶板不被实际射击代码命中。测试失败必须返回失败状态。
4. 测试调用游戏实际使用的逻辑，不能另写一套简化逻辑只供测试通过。
5. 无窗口运行只能证明部分技术检查通过，不能据此宣称画面、鼠标操作和驾驶手感通过。
6. 能实际打开窗口时再做图形检查；能真实截取画面时保存截图。不能完成的图形或操作检查标为“待用户验收”，不得虚构截图和试玩结果。
