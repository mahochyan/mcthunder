## 1. 本单必须留下的可观察结果

每一炮的穿透动画都来自刚刚发生的同一份结算记录。

## 2. 实现步骤

1. 定义版本化 ShotRecord：shot_id、发射者/目标实例、弹种、规则版本、命中时间、种子、车体与炮塔变换快照、按顺序的装甲/模块交点、状态前后值、停止原因。

2. 战斗解析输出不可变记录，效果、HUD 和回放只订阅；不允许回放再调用伤害函数或重新随机。

3. 为命中目标创建纯显示的剖面副本，按命中瞬间局部变换显示路线、装甲接触和受损模块；副本无物理碰撞、AI、伤害和全局输入。

4. 做右下角2—3秒回放，连续命中可以覆盖或有上限短队列；不暂停正式战斗，用户能关闭该窗口。

5. 缺失/非法记录时显示失败原因，不播放虚构击穿；未穿和跳弹也显示对应结果，不强行画进车内。

6. 只保留最近有限条记录，必要时导出单条 JSON 调试；禁止保存无限增长的逐帧战斗数据。

## 3. 自动检查与集成验收

下面是要实际实现和运行的验收案例，不是已有测试通过记录。每个测试调用真实生产逻辑，记录源码SHA、命令、种子和结果。

**T010-01**：记录命中发动机但未命中乘员，回放只高亮发动机；模块前后状态与记录一致。

**T010-02**：记录后目标转动炮塔、被删除或重生，回放仍显示原命中瞬间布局。

**T010-03**：重复播放同一记录10次，实战模块、得分、弹药均不改变。

**T010-04**：关闭回放前后，同种子同场景的真实伤害结果一致。

**T010-05**：一次未穿命中，回放轨迹不能穿过外甲并演示乘员伤亡。

还必须重跑此前相关回归、资源导入/脚本检查与有限帧启动。调整旧测试只能因获批规则变化，不得删断言掩盖问题。
