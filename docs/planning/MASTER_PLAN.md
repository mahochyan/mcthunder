# 像素战雷：从001到可交付v1.0的完整开发计划

制定：2026年9月7日｜仓库：mahochyan/mcthunder｜后续工作单：002—036，共35张。

> 做一款“低模方块风、按装甲和内构结算的小规模坦克战”。不是完整战争雷霆换皮，也不是逐方块体素世界。
> 本包提供可以分单执行的工程计划，不是已实现游戏。本次没有修改远程仓库，没有独立运行或签收001。

## 一、先定义完成的样子

首次打开游戏 → 中文菜单/教学 → 车库选车与配弹 → 选地图和难度 → 4对4占点 → 阵亡/维修/重生 → 胜负结算 → 记录成绩 → 再开一局。
靶场可查看装甲与内构并做射击实验；三个固定挑战提供有目标的单人玩法。

| 领域 | 1.0必需内容 | 明确不在首发 |
|---|---|---|
| 运行 | Windows x64离线单机、键鼠、独立游戏包 | 手机/网页/主机/在线匹配 |
| 载具 | 原创轻、中、重、固定战斗室歼击车各1 | 飞机、海战、步兵、几十辆科技树 |
| 场景 | 2张战斗图+1靶场 | 开放世界、无限随机地图 |
| 模式 | 4对4单据点、3固定挑战 | 多人竞技、赛季、战役编辑器 |
| 战斗 | AP/APHE、角度穿甲、模块/成员、维修/起火/殉爆 | 真实材料学、逐体素穿甲、真实履带链 |
| 反馈 | 真命中记录驱动的穿透回放、受损提示、音画反馈 | 凭空演示弱点/伤亡的假回放 |
| 产品 | 教学、车库、中文、设置/改绑、战绩存档、菜单/结算 | 云存档、账号、复杂经济、氪金 |
| 质量 | 可重玩、严重问题清零、实测性能和明确限制 | “完美还原”、未经测试的硬件承诺 |

关键底线：没有整车总血条；画面可简化，但同一条件下伤害能解释。所有数值是游戏设计初值，不冒充历史真实性。

## 六、你、Codex、审核者怎么合作

你把包放入工程后，只发NEXT_CODEX_MESSAGE.txt，本轮授权002。
Codex完成源码、自检、文档并按已有授权推送仓库，给出分支和实际提交SHA。
你试玩，把DELIVERY报告、SHA、截图/录屏和具体问题发回本对话。
审核者检查该提交与测试证据；能够运行的检查才写实际通过，不能运行的内容如实标注。
未通过给NNN-R1整改单：复现、原因、修改边界、新回归、通过条件。通过后再授权NNN+1。
用户只需判断“能否启动、是否符合预期、哪里不好用”，不需要手动拼接代码。

## 七、工程原则，避免后期推倒重来

1. 配置可共享，实例损伤/成员/弹药/装填不可共享。新车型主要增加数据，不复制伤害系统。
2. 玩家和电脑都发同一种控制命令，炮塔/炮弹/穿甲/损伤共用规则。
3. 碰撞、装甲、内构与外观分层，但位置/尺寸/部件旋转一致。
4. 真实结算先发生，再生成记录；HUD、音效和回放只读取结果，不能反向决定伤害。
5. 有早期命中几何测试、持续回归、独立导出探路，而不是最后才发现脱离编辑器不能玩。
6. 1.0先不联网；以后联网另立技术方案，当前不建设空壳网络架构。

Godot Resources、物理查询、命令行和导出、user://存档的官方依据集中在SOURCE_NOTES.md；本项目具体玩法属于此计划的设计选择。

## 八、最后怎样叫完成

不是“所有工作单写了完成”，而是同一个构建满足：所有必需功能可达；P0/P1为0；真实测试与构建SHA对应；独立运行、保存/恢复、重开正常；素材来源可追溯；实测范围和已知限制清楚；用户接受具体版本。
平台商店账号、审核、费用和正式公开上传不包含在“已完成”中，需用户另行授权和到时核实。

## 九、范围超出承受能力时怎么收缩

优先减装饰物种类、镜头花样、粒子密度和额外英文润色；其次经用户批准暂减挑战数量或车型/地图数量并更新首发范围。
不砍装甲/内构一致性，不保留假回放，不用崩溃/丢档和穿墙伤害换内容数量。
本计划本身已将飞机/联机/体素破坏等放到未来。任何进一步缩减都要明说，不能宣称仍已交付原定四车两图。
