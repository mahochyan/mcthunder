# 033 性能与长局测量方案

正式工程验收依赖 032；当前先准备测量入口和有界日志修复。`--verify-performance` 是显式安装诊断参数，普通游戏仍使用原来的启动、失焦暂停与存档流程。诊断使用隔离设置/进度、真实 Windows Release 渲染器、四种历史车型、八 AI 和两张正式地图；只有该无人值守入口跳过失焦自动暂停，以保持测量负载。

默认运行 1800 秒实际墙钟时间，并至少完成 20 次场景生命周期。长阶段每段最多 300 秒，轮换地图和三档特效；对局可自然结束，也可由正常返回接口退出，报告区分负载测量和完整比赛。后续补足的短周期测试负责创建、倒计时、退出、一次性终结和资源释放，不冒充 20 场完整比赛。

记录每帧墙钟耗时及 p50/p95/p99，另记生产物理耗时、渲染 CPU/GPU 计时、活动车/残骸/炮弹/回放/声音/特效、节点/对象/资源与静态内存。GPU 计时不可用时明确标记，不用零值冒充零开销。每两秒采样，一分钟写一次阶段报告；帧记录容量有上限，超限不得宣布完整测量。

工程目标是 60 FPS；任何实际结果只适用于记录中的硬件、驱动、分辨率与负载。正式采样期间不同时运行其他 Godot 压测。短入口预检不作为长局或最终性能结论。

发现自动交通日志按比赛编号持续增多。033 改为 `user://diagnostics/traffic/match_00.json` 至 `match_09.json` 十槽轮换，每份最大 2 MiB，超限在打开文件前拒绝，保留旧证据。测试迁移的是日志定位约定；采样字段、拥堵定义、生产结算和原有断言含义保留。旧用户目录日志不自动删除。

基础活动预算继承已有系统：八辆活车、64 发活动母弹、每弹最多 12 条不递归破片、12 个残骸、16 条有界历史射击记录、一个活动回放视图、32 个声音槽、12 组短时特效。实际队列实现与历史计划“回放队列 2”不同，按当前有界实现测试，不把计划数字写成已运行事实。
