## 4. 007：把接触与终止分开
当前006是首个装甲接触就finish；007允许穿透/反弹继续。
必须增加projectile_contact(record)或等价的记录提交接口，与projectile_finished(record)分开。
接触可多次；终止一次。先更新内部状态/记录，再通知外部；取消清理深度门继续保护重入。信号监听者可能重置场景，返回后检查state仍有效与round/token未失效。

ArmorResolver输入：
- contact：entity/life/part/surface/point/normal/has_thickness/thickness_mm/状态。
- incoming_direction：接触时velocity归一化，不用相机方向或开火时方向。
- 当前Budget：scale k、累计消耗 C、已跳弹次数。
- 距离曲线P_base(s)：s是本发实际累计路程。
输出：penetrated / perforated_stop / stopped / ricochet / ricochet_limit / unknown_armor / grazing_unresolved / invalid，含角度、等效厚度、before/after、反射方向和诊断。
函数不直接更改车辆、任务或飞弹字典；管理器提交返回结果。

游戏近似规则（不是历史材料学）：
P(s)=max(0,k*P_base(s)-C)。初始k=1,C=0。
夹角θ=acos(abs(d·n))，0度正入射。线性距离曲线的s严格递增、值非负且不递增，范围外夹到端点，不外推负值。
先检查unknown和无效输入；接近90度用grazing_unresolved终止，不除以接近0。
默认75度及以上进入跳弹规则，最多一次；这是集中配置的TEST ONLY初值。反射d'=d-2(d·n)n；速度乘0.6，预算保留0.5。为保持剩余预算一致，k和C都乘0.5，不能只清空C。
其他情况T_eff=t/abs(d·n)。P>T_eff则C增加T_eff后继续；相等仅穿孔且剩余0→perforated_stop；不足→stop。背面接触使用相同厚度成本并记backface，不默认免费出车；不把每块板生成的显示内表面再扣一次。
UNKNOWN厚度不等于0，返回数据不足并停；标准测试板可以使用明确设计值，不标历史verified。
速度不因每次穿甲自动再乘一套能量公式：本阶段穿深预算与速度之间没有真实材料耦合，反弹速度损失为独立游戏规则。后续升级要统一规则版本。

### 同一物理步剩余时间
当前remaining_dt内先提议自由运动子段h→查询→若碰撞在t，实际只消耗h*t（若射程裁短先乘alpha）。更新position/velocity/age/distance，再解析装甲。
继续/反弹后重新规划remaining_dt，不重新使用完整delta，不把旧段后半截按旧方向照走。
刚处理面用精确身份加起点容差过滤，仅过滤该面0距离重复接触；不能排除全车，也不能位置硬跳几厘米越过下一层。过滤须在选择首接触之前；同位置其他面保持候选或明确几何歧义，不静默清空。
每物理步最多8次装甲接触、每发最多32次接触、跳弹最多1次（初值）；上限触发明确budget终止，不静默丢掉其余路径。

穿透测试靶不应同时在LAYER_WORLD上当不可穿墙：把其装甲面放入布局快照，只有背墙/地形走WORLD；旧TargetBoard仍可作为普通世界靶，不能改坏006。
旧接触计分由第一次有效contact触发，按projectile+target生命期去重；终止事件不再又算一次。旧未知夹具的contact-only策略必须显式TEST ONLY/legacy，不能成为正式历史装甲的回退。

007黄金用例：P60/40正面余20；P60/80不穿；40mm@60度等效80；P70穿40再遇40停止；P40/40穿孔停止；74.9/75/75.1度；两次跳弹；前后向；同一帧多层；world挡墙；unknown不按0；消耗不恢复。

## 5. 008—010：毁伤与记录
内部模块必须由已穿过该目标外部防护的路径授权，不因曾穿透另一辆车便能跨目标伤内部。外部履带单独标识。
DamageResolver输出delta；状态提交后生成DamageEvent。VehicleCapabilities从损伤与岗位推导统一限制。无整车生命条，但模块可以有明确游戏耐久。
ShotRecord从007就逐次追加接触，在010冻结并用于回放。规则版本、内容版本、命中时姿态、预算、模块before/after和终止原因保存。回放不重新投射随机碎片或再算伤害。
随机性如以后启用：每发独立rng状态，记录实际结果；不能只凭seed保证跨引擎版本位级重放。

## 6. 012—019：AI和比赛
AI只能生成命令；感知模块产生可见观察/last_seen，控制器不能偷偷读取未被感知的目标实时位置。
MatchDirector拥有比赛时钟/阶段/票数/重生；先收集同tick事件，再一次计算结果。死亡与结算分别幂等。
AppFlow管理场景与输入所有权，关闭菜单不补发鼠标点击；场景切换令旧异步回调失效。

## 7. 020—030：内容与产品
VehicleContentPackage将历史身份、来源、布局、武器兼容、外观manifest绑定。UI不直接加载任意用户路径。
AmmoInventory维护rack/chamber/in_transfer，任何装填/补给/选弹都满足守恒。
ProfileStore保存局外成绩/研究/配置，原子写入和版本迁移；比赛结果有唯一match_id防重放奖励。
AppFlow页面必须能进入和退出。渐进合并UI，不能同时保留两套控制者和两套车库数据。

## 8. 保持有界
活动车、飞弹、碎片、每步接触次数、历史记录、音效和特效都有上限。越界明确拒绝/回收，不以悄悄删掉已接收炮弹保性能。
性能优化基于Profiler测量，不为“架构漂亮”先换引擎、建ECS或复杂空间树。

# 接手模型连续执行协议（替代逐单等待上一位GPT）

## 1. 权限
用户把接手提示词交给下一模型后，下一模型负责007—036内部开发、设计、自测、文档与阶段推进。无需上一位GPT再次签收。

main默认保持原状；使用开发分支链推进。需要正式合并main、发布tag/release时由用户明确批准。

## 2. 每阶段相同的执行循环
读取实际代码与任务 → 确定最小实现方案/受影响接口 → 写能暴露风险的测试 → 小步实现 → 固定引擎导入/解析 → 单元/集成/真实输入/图形证据 → 自审diff与日志 → 提交与回退点 → 更新状态/下一动作。

工程条件通过后继续下一单；不要发“本单已完成，等上一位GPT回复”并无意义停转。
模型单会话能力有限时，保存进度和NEXT_ACTION，说明实际已做和未做；不承诺会在后台继续完成。

## 3. 状态要分开
implementation：planned / active / implemented / blocked。
engineering：not_run / failed / passed_self_review / passed_independent_review。
human：not_run / partial_observation / accepted / rejected。
content_history：test_only / research / verified_release_eligible。
release：not_requested / candidate / approved_by_user / published。
自审不是独立评审；人工没看图不标accepted；游戏能跑不等于历史资料已核实。

## 4. 分支与基线
007从已核对的006登记开发HEAD开始，其余从前一工程通过的开发候选继续。每单一个work/NNN-name分支或同一阶段集成分支均可，明确父SHA。
开始前git status/HEAD/分支远程引用；工作区脏则保留并识别，不用reset --hard/clean -fd解决。
先commit实现，再测候选；测试需要改代码则生成新候选重测相关项。源码、证据和登记提交可以不同，但要比较运行文件树保证归属。

## 5. 测试证据
四类证据不可互相冒充：纯逻辑、场景集成、实际图形、真人体验。
命令、引擎版本、完整SHA、stdout/stderr、退出码、timeout和实际运行参数都保存。PASS字符串与退出码独立检查；脚本出错退出0也判失败。

数学真值独立算，不调用被测函数生成期望值。近端点不冒充恰端点；炮口距离不拿车体中心代替。
未留存的历史输出标缺失，不补造。

## 6. 负例隔离
坏配置、旧版本变异、存档破坏在独立临时副本执行。不得先写坏原工程再靠user目录旧备份自动覆盖恢复。

原工程只读核对，变化就报告，不自动写回“正确版本”。

## 7. 缺陷优先级与返工控制
P0：数据丢失/凭据泄漏/破坏工程/无法回退；立即停止相关写入并保留证据。
P1：无法启动、崩溃、核心命中/伤害/计分错误、卡在菜单、接受发射却无声丢弹；修复后才能通过依赖阶段。
P2：局部界面/小范围行为问题；若不影响本阶段主流程，可带问题单推进。
P3：美化、文档小差异、非关键冗余；集中处理。

不为每个小问题开启R1/R2循环。一个阶段最多集中一次自审修订批次；如仍有P0/P1继续修真实阻断，但不藉此扩展验收范围。识别新风险先说明影响和反例，不为了“审核严格”无限找边角。

# 已经遇到的坑：接手时不要重新引入

## 运动与坐标
- 角度与弧度混用；前向-Z对应的atan2符号；车体非零yaw下瞄准收敛必须独立验证。
- global_transform已包含父链，不能再乘一次；世界空间示踪线不能跟随车辆拖动。
- 模块有局部旋转，法线要乘完整box_world；查询夹具与可见车体尺寸要匹配。
- AABB相交不是包含，粗筛不能宣称精确穿插。

## 调度与命令
- submit只复制暂存，唯一物理入口consume一次；别让AI手动apply和默认零命令各执行一次。
- 暂停不自动保护公开方法；Gunner/Manager入口分别合法性检查，不用冷却遮掩暂停漏拦。
- 新生飞弹born_tick必须实际比较；仅try_spawn返回pending不足以证明本tick后半段没推进。
- 装填/宽限只在物理时钟扣一次；process_frame不等于physics_frame。

## 查询与结算
- WORLD与车辆驾驶粗碰撞不能替代装甲面；炮根→炮口遮挡不能删除。
- 世界命中t=distance/segment_length；inside hit法线零是未知不是没有墙；face_index=-1可合法。
- 查询ok与complete不同；缺变换不能用IDENTITY伪造完整成功；共面未决不等于miss。
- 距离裁短要同步位置/时间/速度/路程；接触t基于裁短段，时间先乘alpha。
- 同面片三角形对角线去重，不合并不同层；开口环只匹配相邻边，且按part_id隔离。
- 排序比较器必须传递：严格距离+确定性身份，不在比较器中用epsilon临时换规则。

## 生命周期
- 身份包含round/entity/life/shot/projectile；同名新实体不是旧实体。
- finish先标终态并移出集合，再通知监听者。
- cancel_all/cancel_by_shooter用_cancel_depth，嵌套清理期间发射仍拒绝；不靠最后clear吞新弹。
- 旧轮次先拒绝再改target.hits_taken，不只让任务gate拒绝分数。
- 快照字典复制；执行查询时统一采样世界与车辆；STALE签名对应实际使用快照。

## UI与证据
- Control容器父层/CanvasLayer要正确；检查重叠不仅检查出屏。
- F6、暂停、Inspector之间输入所有权清晰；关闭点击必须等释放后重新武装开火。
- 临时世界墙要清理；UI编辑参数与实际碰撞体应用一致。
- frame_post_draw后捕获状态才是图片状态；低FPS可能已命中，不能用in_flight文件名造证据。
- 15/60实际帧率对比不是30/144请求值对比；记录飞行窗口实际delta。
- 自动图像与文字核查不是真人体验签收。记录“弹速可见”不能扩大成全流程接受。

## 数据和文件安全
- verified必须绑定来源、具体车型和字段；通配出现在来源模式，待验证字段应是具体ID。
- 负例在临时副本写坏配置，不原地破坏后恢复，更不让旧备份覆盖用户合法修改。
- 发行不要上传不可公开再分发的原始素材，不打包系统字体和工具安装包。
- 0.9/300是0.003，不用大容差包容错误真值；墙心与接触面距离不同。
