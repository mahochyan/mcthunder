# 013 实现方案

从012工程通过候选继续 `work/013-ai-drive`。按用户007—036连续授权推进，外形遵守MODELING_STANDARD。保留同一VehicleActor命令消费、CharacterBody碰撞与Capabilities，不直接写AI坦克位置。
本单期间用户将总定位改为low-poly低多边形。同步更新总计划/规则/025美术单与车库名称，并以分面圆柱轮组/舱盖、锥形炮管迁移当前模型；原装甲与毁伤数值不变。圆形件预算测试按新策略从“最少体素数”改为结构保留与三角形/批次数预算。

- `DriveNavigator` 读取随项目分发的有限路点JSON图，验证ID/有限坐标/边宽/连通引用，用确定性A*返回路径或明确unreachable。最小路段净宽 = 车型实际驾驶碰撞宽度 + 0.6m。图为场景配套设计，不宣称自动覆盖任意地图。
- `AIPathDriver` Node作为控制者，`poll()`生成VehicleCommand，由Actor现有唯一物理入口提交/消费。新增控制者是否本地相机的方法，AI不抢走玩家相机/键鼠。驾驶参数和毁伤能力仍来自真实actor。
- 朝下一路点计算水平角，有限转向，大角度先停车转向，拐角减速，达到目标驻车。目标无效、死亡、状态代次改变、解绑/新局取消旧路径；失败不静默重启。
- 前方WORLD/VEHICLE近距探测只读真实物理，排除本车。友车阻挡先让行；`StuckDetector`按实际位移/期待推进计时，有限倒车+转角+重算，三次仍无进展明确失败并停止。重算间隔至少1s；事件日志有界。
- 中文车库AI驾驶实验室可达，五个固定案例：直行、直角、绕箱、窄道拒绝、障碍倒车脱困/两车会车。选择案例显式重开训练；玩家可开车挡路观察，路径显示为可关闭的训练辅助。
- 自动测试调用真实控制器和Actor物理执行链，检查路线/宽度/碰撞/状态代次/毁伤/重算频率/有限失败；不能用传送实现到达。窗口从正常按钮进入，观察真实AI绕障到达。
