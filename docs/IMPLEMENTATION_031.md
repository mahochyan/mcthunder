# 031 独立发行包候选

`tests/build_release.ps1` 固定 Godot 4.7.2 官方普通版和 Windows x64 Release 模板，从明确 Git 提交提取全新源码目录。没有旧 `.godot` 缓存，先导入，再运行全量回归，然后导出、写引擎/字体许可，打包并在工程外含中文和空格的路径解压验证。失败保留诊断输出，不生成 VERIFIED_CANDIDATE。构建清单绑定源码、引擎、模板哈希、规则/数据 schema、回归数量和各文件 SHA256。

Windows Release 预设移除测试、日志、工具、建模源文件、规划和开发脚本。动态加载的四车、两图、三项挑战、教学、音效、本地化与字体许可显式保留。GLB 导入器从嵌入图像生成的车型 PNG 是导入依赖，必须一并保留；不能因文件未手写或属于生成物而排除。

正式模板没有编辑器的外部 `-s` 脚本入口，所以安装验证为可选的 `--verify-installation` 诊断模式。它使用隔离用户目录、真实车库/地图/挑战/教学场景、正常键盘驾驶与开炮，在限定时间内返回结果并退出。安装目录不写测试数据；测试脚本不在包内。诊断递归检查整个 PCK 路径，实际加载 GLB 的材质依赖，避免仅用 `ResourceLoader.exists` 把缺材质误报为完整模型。

构建初次全量检查发现的旧问题先修复再重建：工业测试采用正常主场景的脚本依赖加载顺序，解决仅测试启动顺序导致的退出资源占用；山村 AI 阻塞恢复检查发现出生点到主路的直线连接横穿其他停车位，已用左右双通路先驶离停车排再横向并入主路，保留单边封锁后的替代路线。原七个 AI 必须到达中部的断言未删除或降低。相关复测：村庄自然战斗 21/21、地图 27/27、历史车型道路 17/17；日志见 logs/031/*-departure-r2.log。

当前阶段不能仅凭预检宣布独立包交付。被测提交、最终全量结果、实际 ZIP 和未验证项在 `DELIVERY_031.md` 中登记。真人试玩、跨机器兼容、平衡和长局性能分别验收。
