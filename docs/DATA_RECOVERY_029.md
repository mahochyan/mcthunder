# 数据与恢复说明

Windows 用户数据位置：`%APPDATA%/Godot/app_userdata/PixelArmor`。数据写入用户目录，安装目录不需要写入权限；游戏不保存局中物理快照，也不连接云端。

设置在 `settings/input027.json`，格式 schema 2。按键、音量、辅助选项、字号、灵敏度、简体中文和已确认的显示模式保存在一起。`input027.json.bak` 是上次成功保存前的有效设置。schema 1 自动迁移；更高版本文件禁止覆盖，包括重置操作。

进度在 `profiles/commander.0.json` 和 `commander.1.json`，格式 schema 3。两个槽交替写入，包含教学、挑战成绩、研究、解锁、配弹和最多 128 份比赛收据。读取最高有效 revision；一槽损坏时恢复另一个并提示。两槽均无效时保留原件、禁止写入。schema 1/2 自动迁移；任一槽来自未来版本时禁止保存与重置。

正常保存先写临时文件并重读校验，保留有效旧数据后才替换。设置损坏原件在下次保存前复制为 `.corrupt-*`；档案坏槽在替换前同样保留。保存失败会提示，显示预览保存失败会自动恢复。全屏使用桌面分辨率，尺寸选择用于窗口模式，10 秒内不确认就回退。

手动恢复：先关闭所有游戏实例，复制整个数据目录到自己的备份位置，再处理损坏副本。设置可用已知良好的 `.bak` 替换主文件；档案应保留两槽，让程序校验后选取有效数据。不要手动修改 revision、比赛编号或资源 ID。

如异常退出后提示锁占用，先在任务管理器确认全部 PixelArmor/Godot 游戏进程已退出，再把对应 `.lock` 目录移到备份目录。程序不会仅凭时间长就删除其他进程的锁。文件来自更高版本时，应使用对应或更新版本，不应通过删字段强行降级。

车库设置中分别提供“重置全部设置”和“重置游戏进度”，均需确认。后者恢复初始研发/解锁/配弹并清空成绩；保留档案身份和递增比赛序号以拒绝旧比赛重复奖励。重置前可自行备份整个用户数据目录。

自动损坏和写入失败检查仅操作 `user://tests/` 下的隔离档案，没有修改玩家正式数据。用户亲自重启和备份恢复验收尚未执行。
