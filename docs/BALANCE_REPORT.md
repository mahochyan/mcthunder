本轮完成实际四车两弹种矩阵和八局固定种子筛查，没有修改历史装甲、装填、炮塔转速、穿深或挑战阈值。主要结果是验证差异并建立可复查基线；真人四车两图试玩仍为 PENDING。

1536 发水平入射几何夹具覆盖四车互射、100/500/1000 米、前后左右、两种高度和两种横向偏移；所有发次终结，全部有装甲接触，962 发产生真实毁伤。14 项验证通过。768 组成对比较中，AP 在 90 组造成更多乘员伤亡，APHE 在 140 组造成更多；其它为相同乘员计数，不代表模块效果相同。详细 CSV 和实际表面名称见 `docs/evidence/032/matrix`。采样点并非真实对局命中概率分布，不用这些计数给车型排名。

示例：M26 对 M4、100 米、正面炮塔高度 2.1 米、横向偏移 -0.45 米时，AP 后剩余四名乘员，APHE 后剩余五名；M4 对 M4、100 米、后方同高度偏移 +0.45 米时，AP 后四名、APHE 后三名。结果来自同一个生产 ProjectileManager / ArmorResolver / DamageResolver；没有为了让两弹各赢而修改参数。

车型定位来自公开配置差异：M24 更轻快、M4 为起始通用车、M26 的防护与火力不同、M36 为开放炮塔炮车。它们不能通过“后解锁就秘密加成”实现定位。普通模式轻量研发为 M24 80、M36 120、M26 180 点；训练模式允许研究/试用，继承 022，未为本次测量增加刷取要求。三星条件继承挑战 v1，侧击经济目标最多两发、速通 80 秒；不把脚本最佳成绩当作真人难度接受。

矩阵及比赛对应 29fd4ae144dbb656fcc4361ecbb4450931c90389 的测量工具；比赛在提交前启动，随后这些脚本原样提交，具体源归属写在 `logs/032/29fd4ae144dbb656fcc4361ecbb4450931c90389/swapped-matches/RESULTS.json`。后续查询优化 36abe97 的 1536 发 JSON 与此前逐字节相同，SHA256 为 `AC6FABD294E72B45E998677EB7F96BB731012F78D0C306389CCC082532592FCA`。这些中间测量不冒充最终 RC 的全量同提交回归，RC 要单独验证。

最终核对发现：旧夹具只停用 actor，显式 PAUSABLE 的 tank/gunner 子节点仍会更新姿态；因此最终干净构建与旧矩阵有 307 个数值字段不同，虽然接触、毁伤、配对计数相同。旧记录保留为原始观测，不把它当作跨运行确定性基准。测试修订 `666aea98dff5be17cc482b190661a201d1c0156b` 停用全部子节点，并新增四车姿态不变断言；没有修改运行源码和包。

修正后的固定姿态矩阵分别在当前查询实现与 `24ebb87` 的优化前查询实现运行，各 **18/18** 检查通过，1536 发完整 JSON 逐字节相同：`3B90E05682868BDD67D0CDA8C680AD74BC1C4EC094D2BAB6EAE54A9A86A09940`。基线是隔离目录中仅恢复该查询文件，具体组合来源见 `logs/033/fixed-matrix-comparison/PROVENANCE.json`。当前有效 CSV 在 `docs/evidence/032/fixed-pose/`。结果仍为 1536 次接触、962 发毁伤、AP/APHE 90/140 个乘员优势点。031 原始 2786 项总数不追加改写；这 36 项是明确单列的补充验证。

冻结的是首版 RC 的规则内容，不是用户接受 1.0。规则文件和内容数据的精确哈希另存 RULESET_1_0_RC.json；后续改数值用新规则修订和独立补丁，不覆盖当前证据。
