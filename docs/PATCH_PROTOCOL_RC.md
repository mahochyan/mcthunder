# 候选冻结与补丁流程

可交付版本由源码提交、BUILD_MANIFEST、EXE/PCK 哈希、ZIP 校验和对应测试结果共同确定；“最新工作目录”不是发行身份。旧候选和失败日志保留，文档补充提交不改变已经导出的二进制源码身份。

收到问题后，先用原包复现并记录构建标识、操作和严重程度。崩溃、坏档、不能开始/结束、错误命中等 P0/P1 必须修复；非阻断显示问题登记具体复现与影响。修复在新的 `codex/` 分支和新版本号完成，保留最小补丁及实际回归，再生成新的候选目录和清单。

存档升级使用已验证的迁移与双槽写入。旧包遇到未来 schema 会拒绝覆盖，应从用户自己保留的兼容备份恢复；不能为了回退删除新档或伪造版本。设置和档案的位置、备份与坏文件保留规则见 DATA_RECOVERY_029.md。

回退使用前一个完整 ZIP，解压到新的目录并保留同名 PCK。不要单独替换 EXE 混搭另一版本 PCK。新版本验证失败时保留原候选，不把失败包覆盖成“最终版”。

工程自审、真人接受、历史内容核验和对外素材权利分字段记录。未经用户明确动作，不代签 1.0 接受、不创建公开 Release、不上传商店、不购买签名。后续车身后坐、悬挂、特效细化和 99A 集成另起工作范围。
