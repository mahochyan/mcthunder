基线 `fc8a6823bbd5d06932103d890779fb447cf0cda9`，分支 `codex/mainline-027-continuation`，固定 Godot 4.7.2 / Compatibility。原 main 与 development 工作区保留。

实现加载覆盖层、取消及错误返回、切换代际检查；快速开始/重开只生成一场比赛。比赛中返回需确认，取消恢复原暂停或再出击状态。新比赛完成初始化后才登记正式奖励凭据，失效场景不能结算到新一局。

结算显示累计命中发数、击穿发数、击毁、阵亡、无争夺据点驻守时间及最后死亡原因。命中来源为生产 ProjectileManager 的装甲接触信号，一发穿过多层只计一次；死亡来自 TicketLedger 接受的真实车辆死亡记录。统计随最终结果冻结，不依赖仅保留 128 条的滚动事件列表。重复结算不再次追加文本或奖励。

多层弹窗以实际显示先后分配输入优先级，避免确认对话框下的暂停菜单抢走 Tab/Esc。结算文字可滚动，重开与返回按钮固定可达。

## 验证分类

- `run_app_flow_checks.gd`：缺资源/错误类型恢复、三次加载取消、十轮双图切换、重复点击、暂停与阵亡退出确认、弃局结算及重开。弃局和阵亡用生产入口构成明确的集成夹具，不声称赢得比赛。
- `run_team_checks.gd`：增加真实飞行/装甲查询产生的双层接触统计、重放/旧局/旧 life/友军排除和阵亡去重。
- `run_app_match_cycle.gd`：两张正式地图，由实际 AI、票数和计时规则自然结束；玩家不驾驶、不射击，阵亡后仅调用正常再出击入口。不直接写票数、损伤或胜负。隔离内存档案用于凭据检查；真实磁盘往返由车库/挑战套件另验。
- `run_localization_window.gd`：真实 720p/1080p 窗口、Tab/Enter/Esc 菜单路径。最后的弃局结果专用于布局验证；不是玩家胜利录像。

失败日志保留：初版后台线程加载导致重复换图时脚本继承解析失败；首次窗口复测发现确认弹窗抢焦点；重复结果的奖励提示变化已纳入回归。

困难猎歼突进测试原驾驶员瞄准正面炮盾叠层，被对手真实弹药殉爆击毁。更新测试驾驶策略为沿原检查点路线等待侧面射角、攻击底部弹药架；敌方 AI、装甲、穿深、弹数、任务目标及成功断言不变。

挑战测试的脚本资源残留可仅通过加载测试脚本复现，无须实例化比赛；改为预载并实例化生产 `app.tscn`，统一依赖解析顺序。没有修改生产静态身份计数器或降低日志错误检查。诊断日志在 `logs/030/*lifetime.log`。
