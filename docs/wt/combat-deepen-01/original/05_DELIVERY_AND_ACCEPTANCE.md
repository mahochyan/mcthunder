# 交付、验证与拒收协议

## 1. 每张子单先设计一页，然后实现

记录当前生产调用链、已有实现、首个待复現条件、玩家结果、修改文件、状态/事件/版本、异常边界和本单不做项。完成这页后直接进入实现/验证，不把设计页当成最终成果。执行范围为当前用户要求的本地深化开发；不包含自动合并主线、付费、公开发布或外部账号写操作。

共享文件的写入先安排归属。已有接口够用就扩展，不因本规范字段名而重命名全项目。新功能的正常入口和最小反馈随功能同交，不能最后只留一组测试脚本。

## 2. 六类交付物

| 类别 | 必需内容 |
|---|---|
| 生产实现 | 真实代码/配置/资源与必要迁移；定义只读，运行状态独立 |
| 源码身份 | base_sha、implementation_sha、tested_sha、final_sha、规则/内容版本，证据提交与被测提交分开 |
| 运行证据 | 实际命令、工作目录、引擎版本、退出码、起止/超时、原始stdout/stderr、检查ID与未执行项 |
| 操作证据 | 正常输入步骤、真实截图或录像、事件记录；有注入/固定姿态的夹具明确标记 |
| 当前限制 | FAIL/INCOMPLETE/NOT_RUN、外部未比较、素材限制、真人/性能状态 |
| 接续回退 | 下一个依赖任务、旧档兼容、git revert范围、旧候选包路径与清单；不能删除用户文件当回退 |

源码快照中未包含的本地制作资源不能悄悄影响结果；若必须参与，单独授权并记录哈希，否则隔离。原始模型字体不随本规范分发。

## 3. 五个验证层，不相互替代

1. 规则/负例：输入是否合法、状态是否完整、重复是否拒绝。
2. 标准夹具：与独立解析答案或已冻结设计预期比较；不可调用被测函数生成expected。
3. 实际Actor集成：真实炮口/弹药/运动/装甲/内构/库存/能力/比赛调用路径。
4. 正常玩家流程与包：实际界面、键鼠、真实等待、正常再出击和持久化。
5. 外部行为/真人：战雷固定版本对照和用户实际体验；无证据不代签。

96个用例是覆盖清单，不是凑PASS的额度。可以细分，不能为了固定数量合并未执行场景。待复现的问题未复现时可以报告NOT_REPRODUCED并保留证据，而不是制造差异；但这不自动覆盖同子单其他必需用例。

## 4. 运行器拒收条件

非预期SCRIPT ERROR、Parse Error、缺真实退出码、超时、必需用例未执行、截图/产物丢失、源码与证据身份不符、必需内容缺失，一律不能PASS。进程exit=0但审计不完整也不能PASS。

保留完整通过/完整但有缺口/不完整三态。反例预期产生的错误须逐ID、明确日志预期，不允许正则广泛吞掉整套件错误。已知失败只沿用已经批准且当前仍有效的登记，不新增未经批准的R3-A等例外。

增加新规则后，允许有明确版本的新预期，但要保留旧规则的回归并说明语义变化。不得删失败断言、拉长正式比赛/改票数/提高速度来制造正确结果。运行器预算只保护执行，不是游戏规则。

## 5. 性能与数量边界

保持性能HOLD：不开展FPS/p95/p99、人数容量测试、全资源优化、重构缓存或批量减面。短场景的仿真时间、速度、距离、实际超时和数值收敛属于功能验证，可以记录；性能差异若阻止测试，点名阻塞，不能私自降低物理精度。

仅验证当前4v4及既有本机双客户端一致性。本单不宣布10v10/16v16、公网或完整账号服务完成。

## 6. 规则迁移与配置事实

所有新规则附old_version/new_version、affected_vehicles/modes、why、sources、migration、legacy_tests、new_expected、rollback。原始参考档案不改；派生工程配置和它的证据claim同时更新，值要相等，来源不冒充。

对标资料缺失或矛盾时使用design/estimated，比较状态NOT_COMPARED，并列出项目偏离。工程初值可由执行模型按本单范围冻结，不逐字段反复申请；不能借此发明官方BR、真实弹药型号参数或精确复合装甲资料。

## 7. 内部包目录建议

```
PixelArmor-combat-deepen-<source_sha>/
  PixelArmor.exe
  PixelArmor.pck
  BUILD_MANIFEST.json
  HASHES.json
  REQUIRED_CONTENT.json
  README_运行说明.md
  KNOWN_ISSUES.md
  EVIDENCE_INDEX.json
  SAVE_MIGRATION.md
```

清单至少记录source_sha/engine/template hash/rules/content IDs/package_kind/required_content/验证范围/known_failures/release_ready=false/public_release=false/human=PENDING/performance=HOLD_BY_USER。

G1和G2可作为范围清楚的中间包；最后G4必须在同一个实际包内完成：两车选择/配弹、河谷正常战斗、受损恢复、同生命实弹死亡与正常再出击专项、自然结算/下一局、关闭后独立重启。正常局不要求出现全部罕见事件，专项与自然局分开。

**必需两辆现代车缺失后改用历史车通过，不符合本总单。**未知资产许可不可由模型自封authored_asset来解决；必要时使用权限明确的替代工件，保留差距。

## 8. 进度汇报格式

只汇报：本轮玩家新增能做什么；实际修改/被测SHA；原始失败及修复后的关键结果；当前未完成项；下一项。不要再用提交数、文档数、调查轮数和总PASS数代替玩法进度。
