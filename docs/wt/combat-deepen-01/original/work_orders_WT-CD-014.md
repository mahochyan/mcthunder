# WT-CD-014｜陆战拟真出击规则与局外结算

优先级：**P2** · 关口：**G3** · 发布状态：planned

前置：WT-CD-012, WT-CD-013

关联旧单：WT-022, WT-033（仅关联，不覆盖旧职责）

## 依据与边界

现有固定300票/等待再出击/胜负奖励为项目规则，不等于常规战雷Ground RB的个人出击资源。

来源：[R09] [W07]

## 玩家新增能做什么

保存经典训练与原对局，同时增加明确的拟真出击选择、贡献奖励和可靠局外保存。

## 先读的生产入口

`scripts/battle/match_rule_preset.gd`  
`scripts/battle/respawn_service.gd`  
`scripts/battle/team_match_director.gd`  
`scripts/garage/（实际保存与编成服务定位一次）`  

路径是审查线索；后继重命名时只做一次定向定位，不因路径未命中就宣称系统不存在。

## 必须设计

1. 新增ground_rb_like_v1，不覆盖team_standard_300。队伍票池、个人SP、研究收益、修理/补弹费用是四种独立账本。
2. 初始SP、车型费用、重复出击限制和贡献所得由冻结项目表提供；缺真实BR/价格时用project_balance_band，禁止虚构官方BR。
3. 模式选择改变实际规则及信息显示；缺配置车型明确拒绝，不回退到历史/训练车。
4. 重生请求采用校验→预留→生成确认→提交扣费；出生被堵/失败/取消释放预留。重复请求幂等，余额不能负值。
5. 局外净收益/费用分项记录并只入账一次；本轮不做付费商城、账号服务或真实货币机制。可关闭经济费用但必须标为项目偏离。
6. 资料未核全时允许工程项目初值，不逐字段等用户确认；公开参考与项目差异用DIVERGENCE_REGISTER登记。

## 实现顺序

1. 提取原规则实际调用边界并保持旧模式全部回归。
2. 先本地加入新preset与SP账本，再接编成合法性、费用和贡献。
3. 更新最小模式说明/禁入原因供UI，不重做科技树页面。
4. 实现保存事务/收据迁移及重启验证，不把本地收益当可信线上进度。

## 必须交付

1. 版本化拟真preset及余额规则
2. 个人/队伍/局外账本分项收据
3. 失败出击回滚与存档迁移
4. 旧模式与新模式正常流程

## 六项验收设计（当前均NOT_RUN）

### CD14-T01｜旧模式回归

操作：使用原team_standard_300完成正常局。

预期：旧规则和存档语义保持，新增行为仅在新preset生效。

### CD14-T02｜个人SP与队票

操作：占点/击毁/死亡后检查双方及个人账本。

预期：不同资源互不串账，收益依据提交事件。

### CD14-T03｜出击失败与重复请求

操作：出生被堵、取消、重发同token。

预期：不重复扣费，预留释放正确。

### CD14-T04｜编成次数与资格

操作：切换车型、耗尽出击次数、资源不足。

预期：统一资格拒绝且原因可见，不生成默认车。

### CD14-T05｜结算重试与存盘失败

操作：重复提交结果、模拟隔离档写失败再恢复。

预期：不重复奖励，故障明确可恢复，不污染真实用户档。

### CD14-T06｜重启与不同规则版本

操作：新包重启并读取旧档/旧比赛结果。

预期：历史结果按原版本解释，未知版本明确迁移或拒绝。
