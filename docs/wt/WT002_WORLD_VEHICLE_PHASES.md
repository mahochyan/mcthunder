# WT-002 团队世界的车辆阶段

基于ac71e21的开发批次。玩家和AI原本逐车完成取命令、移动、瞄准与开火，因而后更新的控制器看见先更新车辆的新位置；瞄准时也混用新旧炮塔几何。现在TeamRange（包括村庄、工业区与正常重生）的同一车辆名单由VehicleSimulationDriver在物理优先级0统一推进，按entity_id稳定排列。

顺序为全车取命令 → 全车命令观察/恢复 → 全车驾驶 → 全车相机瞄准意图 → 全车炮塔机构 → 全车发射与状态发布。原有弹丸100、补给/交通200、比赛300、内部快照400继续执行。驾驶后更新瞄准查询，但所有查询完成前不旋转炮塔几何。实际弹丸仍从当步真实炮口发射；没有用准星射线替代炮弹。

VehicleActor仍是唯一命令消费与执行逻辑的实现者。团队车通过弱引用关联调度器，停止自己的重复物理执行；调度器遵守车辆自身的物理处理开关、暂停和生命周期。阶段间检查generation/control_epoch，后一个观察回调清除前车命令时，前车剩余阶段立即失效。独立靶场与现有单车数值夹具使用相同拆分方法的连续调用，未在本批接入整个靶场的全车调度。

这是观察顺序修复，不是跨平台确定性或真实同时碰撞求解：CharacterBody移动碰撞仍在固定顺序中逐车求解；控制器内部感知查询的固定周期、OS输入时间轴、命令消费确认、网络恢复和完整性能门槛仍待继续。未新增车辆或替代驾驶参数，也未宣称真人手感已验收。

## 证据与未完成检查

`tests/run_world_vehicle_phase_checks.gd`使用真实TeamRange与八辆实际移动车辆，探针只读取各阶段状态。七项阶段/失效检查在修复后通过；`--legacy-order`恢复原逐车调用后，统一输入观察、统一移动后查询、统一炮塔几何和跨车辆失效四项失败，见logs/wt002-world-legacy-order.log。中间版只拆开移动而未分开炮塔机构，炮塔几何检查单独失败，见logs/wt002-world-turret-before.log。

初批团队67、阶段8、命令30、恢复64通过，见logs/wt002-world/ac71e21-world-wip/20260911-121432。地图27项通过，见logs/wt002-world/ac71e21-world-r2/20260911-121621。该轮industrial_checks包含512条逐车路线矩阵，主动停止且结果为失败/不完整，不能算通过；原始部分输出保留。

接续又增加“观察回调释放其他实体”的生命周期夹具，发现类型绑定已释放Node会产生SCRIPT ERROR并中止剩余车辆阶段，见logs/wt002-world-removal.log。该次脚本自身仍退出0，因此只看退出码/末尾PASS不成立；runner的SCRIPT ERROR扫描才是必要判定。调度器现先验证对象再绑定类型，并在每阶段跳过已释放/停用实体。强化后的夹具还要求其他存活车辆继续移动，避免只凭被释放对象消失而误判通过。

最终生命周期补丁：`logs/wt002-world/ac71e21-world-removal-final-r2/20260911-122506`，八项全部通过、退出0，无SCRIPT ERROR或ERROR；同一生产补丁的团队67及事件11项通过，见 `logs/wt002-world/ac71e21-world-removal-fix/20260911-122303`。该目录的旧新增夹具仍有闭包捕获已释放引用的错误，未算通过；随后以WeakRef修复夹具。中间一次WeakRef类型声明解析失败也保留在ac71e21-world-removal-final目录。
