## 3. 结论

1. `run_map_checks` 与 `run_historical_road_checks` 的 **7 条失败不是产品缺陷**：它们**无法在隔离或序列复刻中重现**，而产品的寻路、泊位、宽度、最大包络四项均通过直接测量。
2. 它们**在基线上同样出现**（前两轮已证），且**失败槽位随轮次漂移** → 属**测试台层面的间歇性失败**（长序列、多路线、12000 tick 循环与多变量变体叠加）。
3. 因此**不建议**为这 7 条去改游戏逻辑（会掩盖真实原因）；应把它们**重新归类为"测试台抖动（flaky harness）"**，并把失败样本作为**待加固测试**的证据保留。

## 4. 建议的后续（测试侧加固，**不改语义**）

| 项 | 做法 | 约束 |
|---|---|---|
| 每路线独立世界 | 一条路线一个 `world`（或路线间显式重建地形/图），消除跨路线状态累积 | 断言与阈值**一律不动** |
| 路线间显式收敛 | `free()` 后等待物理帧数并对出生点做**占用查询断言为 0**（本轮已实现该查询，可直接复用） | 不得以"重试到通过"代替修复 |
| 失败可诊断 | 失败时落盘该路线的**逐 tick 轨迹**（本轮探针可直接转正为工具） | 轨迹用于定位，不用于放宽判定 |
| 若加固后仍间歇失败 | 视为**产品级间歇缺陷**，按逐 tick 轨迹继续定位（此时有据） | 需新证据，不得凭"看起来像抖动"结案 |
