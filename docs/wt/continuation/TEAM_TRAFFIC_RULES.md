## 1. 团队任务分配

| 项 | 规则 |
|---|---|
| 分配器 | `AIRoleAllocator`（WT-020-R1）：进攻/守点/侧翼/补给/维修 |
| 迟滞 | 切换冷却 **12 s**；角色**与**目标同时相同才算未切换 |
| 紧急越权 | 不可机动/受损 → `repair`；弹药 ≤25% → `supply`（立即，不等冷却） |
| 覆盖 | 8 槽轮转覆盖 **A/B/C**；机动 ≥3 时固定 **1 辆**走侧翼 → **不会全挤最近点**（实测） |
| 确定性 | 名单按 `entity_id` 排序 → 同输入必得同分配 |
| 换边对称 | 实测两队（南/北出生）**角色分布完全一致**，镜像槽位取得**同一目标** |

## 2. 协调器职责（`TeamCoordinator`）

| 方法 | 作用 |
|---|---|
| `configure(team, objectives, supply, chokepoint)` | 绑定队伍、公共目标与本方补给；把**地图咽喉点**交给分配器 |
| `set_roster(rows)` / `step(now, delta)` | 每步分配任务 + 发布 `friendly_rows`（供 AI 让行） + 发布 `dynamic_obstacles` |
| `status_for(id)` | 该车当前归因类别 |
| `summary()` | **完整归因摘要**：各类秒数、正当静止占比、动态障碍、逐车状态、任务表、咽喉点是否绑定 |

**残骸处理**：`destroyed` 车辆**不进入任务名单**，改为 `dynamic_obstacles`（位置 + kind），供局部导航绕行 → 对应"新残骸/断带车辆作为动态障碍"。

## 3. 交通归因分类（关键：静止 ≠ 堵车）

| 类别 | 判定 | 含义 |
|---|---|---|
| `moving` | 速度 ≥ 0.6 m/s | 正常机动 |
| `engaging` | 有交火标记 | 交火中（允许静止） |
| `repairing` | 维修中 | 维修（允许静止） |
| `immobile` | 不可机动 / 受损停摆 | 失能（允许静止） |
| `legitimate_hold` | 慢速 **且** 位于已占目标 | **合法驻守**（允许静止） |
| `yielding` | 咽喉点内与友军对向相遇且本车 id 较大 | 有界让行（允许静止） |
| `traffic_blocked` | 慢速 **且** 被标记阻塞 | **仅此一类计入拥堵** |

- 让行规则：同队 + 6 m 内 + 对向（点积 < −0.3）+ 位于**地图发布的咽喉点** → **`entity_id` 较大者让行**，上界 **6 s**；咽喉点外或非同向**不让行**（实测）。
- **不宣称 AI 完全消除堵塞**；只保证"有理由的静止不被误计为拥堵"。

## 4. 脱困与目标恢复

- 既有路径层的受控动作：`_drive_patrol_or_hop()`（hop 到最近图节点，不替换目标）+ 失败重试 + 倒车脱困；**不传送、不移除友军碰撞**。
- 本轮实测：被阻塞若干秒后恢复行驶 → 归因回到 `moving`，且**任务角色与目标保持不变**（迟滞保护）→ 对应"原目标在脱困完成后能恢复"。
