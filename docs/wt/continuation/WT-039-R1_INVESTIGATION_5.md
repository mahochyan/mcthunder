## 1. 卡死的物理机制（硬数据）

| 观测 | 值 |
|---|---|
| 卡死位置 | `(-120.8, 4.02, 19.8)` —— **x≈−120 的西侧侧翼坡道**上 |
| 指令 | **`throttle=0.00`、`steer=-1.00`**（原地转向请求） |
| 实际速度 | **`0.000`**，连续 **240+ tick** 位置完全不变（探针在 3194 tick 判 STALL） |
| 该处地面坡度 | **12.2°**（邻域 11.7–13.3°） |
| 坡度上限 | `GameConfig.DRIVE_MAX_SLOPE_DEG = **28.0**` → **远未超限** |

→ **不是"坡太陡"**，而是**声明包络（`max_vehicle_size = 4.2×2.4×8.5 m`）的刚体盒在坡脊处被地面楔住**：8.5 m 长的盒子在曲面上端部会被地面顶住，物理求解器因此把它钉死（转向与油门都无效）。

## 2. 校验器缺口（本轮修复点）

`scripts/maps/navigation_bake_pipeline.gd` 原本只做两件事：
1. 离散采样点（≤3 m）的地面存在性与坡度检查；
2. 包络盒与**地面以外的**世界几何求交 —— 关键行：**`query.exclude = [ground_rid]`**。

→ **地面自身的曲率从未被检验**，因此"地图宣称支持 8.5 m 刚体盒"这一承诺**无法被验证**，缺陷长期不可见。

**本轮补上**：新增第二个求交查询（**保留地面**）并输出 `curvature_failures` / `curvature_blocked`；**`ok` 语义不变**（既有调用方与既有检查不受影响）。

**套件结果（改动后实跑）**：
```
[bake] 1786 samples; failures=[]
[PASS] T018-03 every authored road has real ground and clears maximum vehicle envelope   ← 既有检查仍通过（语义未变）
[FAIL] T018-03b authored roads clear the declared envelope against the ground itself (blocked samples=38)   ← 新增检查暴露缺陷
MAP_CHECKS_FAIL   PASS=45 FAIL=4
```
→ **先前不可见的缺陷现在可测**；同时证明我的改动**没有放宽或收紧任何既有判定**（`T018-03` 与 `bake.failures` 不变）。
