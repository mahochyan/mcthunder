- 触发：按第 3 轮建议完成**测试台加固**（新增"出生点净空"具名检查 + 失败时落盘**逐 tick 轨迹**），加固后连跑 3 轮
- **结论更正**：第 3 轮我判为"flaky harness、非产品缺陷"——**该判断被新证据推翻**，据此更正并留痕

## 2. 轨迹揭示的真实机制（**产品级停滞**）

### 2.1 `run_map_checks` 最大包络代理：**西侧山丘上原地不动**
```
tick=14760 phase=following reason=obstacle_cleared wp=3 dist_wp=20.24 bearing=-44.31 speed=0.000 pos=(-120.734,3.951,20.043)
tick=14850 ... speed=0.000 pos=(-120.734,3.951,20.043)
tick=14970 ... speed=0.000 pos=(-120.734,3.951,20.043)   ← 连续 300+ tick 完全静止，直至 15000 tick 预算耗尽
```
→ 该检查（"maximum-size proxy actually climbs and descends the western hill"）**是真实失败**：最大包络车在**坡度 y≈3.95** 处**被卡住**，速度恒为 0。

### 2.2 `run_historical_road_checks` M26：**爬行至预算耗尽**
```
tick=210  phase=following reason=path_ready wp=2 dist_wp=20.51 bearing=57.62 speed=0.000
tick=5100+ phase=reverse  reason=insufficient_actual_progress wp=0 dist_wp=2.5 speed≈-0.02
tick=5460 phase=following wp=0 dist_wp=2.62 bearing=-0.79 speed=0.000 pos=(-40.399,0.001,17.925)
```
→ M26 在中途进入 **反复重规划 + 爬行**（末段速度 **0.05 m/s** 量级），12000 tick 内无法抵达 → `failed`。**3 轮结果一致（每轮 4 条 M26 失败）→ 确定性，不是抖动**。

## 3. 对第 3 轮结论的更正（逐条）

| 第 3 轮说法 | 现状 |
|---|---|
| "每个失败组合在隔离运行中都成功 → 非产品缺陷" | 隔离成功**不能排除**产品级停滞：在套件的真实长序列中，同一路线**稳定出现停滞**（轨迹为证）。**该推断方法有缺陷**，我据此得出的结论**撤回** |
| "失败槽位跨轮次漂移 → 抖动" | 槽位确有漂移，但 **M26 的 4 条失败每轮稳定出现**；地图侧失败数 4/4/2 亦非纯随机 → **既有确定性缺陷，也有顺序相关成分** |
| "应重归类为 flaky harness" | **撤回**。正确归类：**产品级停滞缺陷**（车辆被卡住/爬行），需要修，不应只改测试台 |

**保留仍有价值的结论**：出生点本身干净（21/21 净空为 0）、图路径与宽度充足（16/16 `request_path ok`）——所以停滞发生在**行驶过程中**（坡道/障碍交互），而非出生或规划。

## 4. 下一轮取证与修复方向（落到文件）

1. **西侧山丘卡死（最大包络）**：采样卡死点周围地形坡度/可通行宽度，与 `map.max_vehicle_size` 的爬坡/净空门限对比 → 判定是**地形过陡**还是**净空不足**；候选修复：`village_definition.gd`（地形/坡道）或 `game_config` 的爬坡限制（**若属战斗/机动参数 → 只登记不擅改**）。
2. **M26 爬行/反复重规划**：定位其 `reverse/insufficient_actual_progress` 触发点与 `_blocked_edges` 累积（`ai_path_driver.gd`），判断是"把可通行边误判为阻塞"还是"转向余量不足"；修复需附**基线对照**证明失败归零且阈值未放宽。
3. 若任一项最终落在**车辆机动参数**上 → 按红线**作为参数冲突登记**，不擅自更改。
