# WT-039-D 语义对照：旧刚体诊断 vs 新产品通行测试

- 依据：用户选择 **D（实际车辆接触模型验证）**，并明确**不覆盖旧刚体测试、不以改语义换 PASS**
- 本文件回答 D 的"一、先明确验收对象"与"五、交付：语义对照"

## 1. `max_vehicle_size` 到底指什么（源码实测，无注释可依）

| 维度 | 值 | 在代码中的实际用途 |
|---|---|---|
| x | **4.2 m = 宽度** | `MapDefinition.validate()` 把 **x 当"车宽"** 传给 `DriveNavigator.request_path(...vehicle_width...)` → **图的宽度门限**；`WorldProps` 净空 = `x/2`；`run_structure_checks` 亦用 x |
| y | 2.4 m = 高度 | 仅 `NavigationBakePipeline` 的**刚体盒**高度 |
| z | **8.5 m = 长度** | 仅 `NavigationBakePipeline` 的**刚体盒**长度（受阻即来自该维度） |

**关键结论**：8.5 m 是**长度**维度，且**仓库内没有任何一处注释/推导说明该数字的来源**；它被当作"地图支持的最大车辆包络"使用，但**从未按刚体模型通过过**。

## 3. 旧声明重新标注（按 D 第 2 项）

> **原说法**："地图已支持 8.5 m 刚体包络。"
> **更正为**："**地图设计目标 / 既有声明；当前刚体校核未通过**（`T018-03b`，受阻 38/1786 采样，集中在 x≈−120 侧翼坡脊）。"

## 4. 两类测试的语义对照（禁止互相替代）

| 项 | **旧：刚体包络诊断** | **新：产品通行测试** |
|---|---|---|
| 测试标识 | `run_map_checks` → `T018-03 / T018-03b`（**保留原编号与真实结果，不删除失败断言**） | 新套件 **`run_flank_crest_traversal_checks.gd`**，断言前缀 **`T039-D`**（独立名称与版本） |
| 被测对象 | **无悬挂、无履带接触的单一刚体盒**（`max_vehicle_size`） | **生产车辆**：生产驾驶、移动碰撞、车体姿态、行动装置与悬挂 |
| 判定语义 | "地图声明包络能否几何通过" | "**具体生产车辆/接触配置在具体测试条件下能否通过**" |
| 结论用途 | **设计目标校核**（当前未通过，保留） | **产品支持范围**（写成"已验证车辆/接触配置及测试条件"） |
| 不许做的事 | 不放宽余量、不改判定换 PASS | 不覆盖旧编号、不用 6.15 m 冒充 8.5 m、不缩放车辆冒充正式车型 |
