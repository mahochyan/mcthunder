## 3. 因此失败被收敛到**驱动控制层**（下一轮取证方向）

已排除：图不可达、宽度门限、泊位占位。剩下的证据指向**特定"泊位→占点"组合下的驱动控制**：

| 证据（第 1 轮已取得） | 含义 |
|---|---|
| `run_map_checks` 槽 2：`following → reverse(insufficient_actual_progress)` **2 次** → `unreachable` | 车辆在 **2.5 s 内仅移动 0.13 m**：不是没路，而是**开不动/转不过弯** |
| 槽 2 首个航点目标 `(3,0,9)`、槽 1 为 `(-3,0,9)`；槽 1 正常、槽 2 卡住 | 差异在**航点相对车头的方位/所需转向**，而非地形或宽度 |
| 失败槽位在不同轮次抖动（cont 1/2、基线 1/3） | 属**边际情形**（turn 余量紧），与"地图硬约束"不符 |
| `run_historical_road_checks`：**仅 M26** 失败且终点 `(±40,18)` | M26（**最长 6.15 m、最宽 3.51 m**）在转向/让位上余量最小 → 同样指向**转向余量** |
| 槽 0 `arrived` 但 `bounded=false` | 运动边界（每 tick 位移/速度）被触发 → 需**定位越界那一 tick** |

**新假设 H5（转向/起步余量）**：在部分"泊位→航点"几何下，驱动器的转向控制无法在"进度不足"判定窗口内把车头转到可前进的方位（尤其对最宽最长车 M26），于是反复倒车恢复并最终放弃。
**新假设 H6（速度/位移尖峰）**：槽 0 的 `bounded=false` 由恢复/碰撞瞬间的单 tick 尖峰触发。
