# WT-007：车型光学配置、观察与炮镜缩放

2026-09-12，开发基线 `b2c56a2`。本批继续 WT-006 驾驶与 WT-007 观察/火控的连接，接入车型镜位、炮镜倍率、望远镜和瞄准反馈。WT-007、WT-008 及完整游戏均未完成；性能专项按用户要求继续暂缓。

## 生产路径与操作

`VehicleContentPipeline.definitions_for()` 为 M4A3、M24 加载各自的 `OpticsProfile`，由 `VehicleDefinition.validate()` 一并校验。`CameraRig` 从当前车辆定义读取配置；正常离线战斗、历史车辆训练和本机联网客户端沿用同一相机与玩家输入实现。其余车辆保留默认光学配置，本批没有完成全车型光学校准。

默认右键按住进入炮镜，Z 在炮镜中循环切换倍率；L 按住使用望远镜，B 按住自由观察。望远镜优先于右键炮镜，自由观察和望远镜均与炮手机械追随分离。倍率切换不改变炮口位置、炮塔转角、装填或弹药；放大视野的鼠标角度灵敏度按投影倍率降低。操作沿用 `InputBindingService`，提示从当前绑定读取；旧设置补充新增动作时保留已有绑定，并选择无冲突按键。

本机联网仍通过 `START_LOCAL_SERVER.bat`、`START_LOCAL_CLIENT.bat` 进入本机训练切片。它不是完整联网比赛、账号系统或公网大厅。

## 车型参数

以下全部为游戏设计值，不是史料测得的瞄具性能。FOV 为垂直视场角；显示倍率是相对默认 70° 第三人称视场的投影比例：

`magnification = tan(70° / 2) / tan(FOV / 2)`

| 项目 | M4A3 | M24 |
|---|---|---|
| 配置资源 | `configs/optics/m4a3_design.tres` | `configs/optics/m24_design.tres` |
| 炮镜垂直 FOV | 30° / 15° | 28° / 14° |
| 对应显示倍率 | 约 2.6× / 5.3× | 约 2.8× / 5.7× |
| 炮镜位置，BarrelPivot 局部米 | (-0.25, 0.45, 0.35) | (-0.20, 0.35, 0.30) |
| 望远镜垂直 FOV | 12° | 12° |
| 望远镜显示倍率 | 约 6.7× | 约 6.7× |
| 望远镜位置，HullFrame 局部米 | (0, 3.0, 0) | (0, 2.8, 0) |

项目坐标为 Y 向上、车辆前方 -Z。炮镜位置由实际 `BarrelPivot.to_global()` 求得，随车体悬挂、炮塔和炮管俯仰移动；镜头前向沿实际炮管方向。望远镜位置由实际 `HullFrame.to_global()` 求得，观察朝向由独立鼠标视线决定；从车体至望远镜位置执行 WORLD 遮挡查询。

配置校验要求 1—4 档严格递减的有限炮镜 FOV，各档范围 5°—70°；望远镜 FOV 范围 5°—40°；镜位必须有限且局部偏移长度不超过 5m。默认配置只有一档 30° 炮镜，不能将默认回退算作车型资料完成。

## 输入意图与实际武器

进入观察时，`CameraRig` 保存炮手原观察角和当前意图点；观察期间鼠标只改变观察朝向。离开全部观察模式后恢复原角度，在 B/L 两种观察间切换不会重新覆盖保存值。玩家命令的 `hold_aim` 由 `VehicleActor` 写入 `TurretRig.observation_hold`，固定物理步执行器据此暂停两根机械轴的追随；因此服务器无本地相机时也可保持炮塔与炮管的局部机械角。车体仍能正常驾驶和转向，这不是保持世界方向的稳定器。

炮镜的意图射线从车型镜位出发，方向取玩家输入角；实际镜头朝向和实际出炮方向仍取当前炮管。这保留了有限机械追随及镜位偏置，避免把当前炮管方向反用为唯一目标、导致鼠标无法继续指挥炮塔。射击继续使用真实炮口与既有炮管遮挡检查，镜头能够看见掩体外的目标不等于炮口可以开火。

望远镜模式的设计行为为仅观察，抑制开火请求。模态输入暂停会取消观察并要求观察键先释放；车辆重置清除倍率和观察状态，联网客户端根据服务器 generation 变化清理对应本地状态。审查发现并复现了跨渲染/物理步误射：望远镜中捕获开火边沿，下一次物理消费前退出望远镜，旧边沿会延迟执行。现于事件、渲染采集和命令消费处清除旧边沿，并要求先释放开火键；专门反例由失败转为通过，窗口检查也验证退出后没有补射且新按键能正常发射。

## UI 与协议

正常战斗 HUD 分别投影意图点与实际炮口命中点，并显示当前光学模式。观察期间保留观察中心标记，隐藏射击意图/实际落点圈。`TurretRig.alignment_error_deg()` 比较实际炮管方向与未受俯仰限位钳制的目标方向；误差大于 0.5° 时显示追瞄中，并与装填就绪状态分别表达。炮管到达俯仰止点但仍偏离目标时，不能仅因执行器到达限位就显示已对准。这里显示的是方向偏差，不是包含距离装定的弹道命中保证。

| 契约 | 本批版本与用途 |
|---|---|
| `VehicleCommandCodec` | v2，新增严格 bool 类型的 `hold_aim`；旧 v1 命令明确拒绝 |
| 本机网络握手/快照 | v3，服务器、客户端采用一致版本，旧协议明确拒绝 |
| `VehicleFramePose` | v1 不变，继续传输实际车体及左右行走机构相对姿态 |
| `SimulationSnapshot` | 既有内部快照记录新增 `observation_hold`，不是完整恢复存档 |

`CommandMailbox` 复制观察保持字段；`NetworkController` 在有效命令时限内维持连续保持值，开火等边沿仍只消费一次。联网客户端采集真实镜位意图、发送命令并显示服务器插值姿态，不本地推进炮塔权威角或发射权威弹丸。客户端原先两车共用视觉层，会导致光学相机同时隐藏敌我装甲；现为每车分配独立视觉层。专项检查读取实际敌车 `Skin_hull` 网格与相机遮罩，并验证本车被排除、对方保留。

## 后续范围

本批没有完成独立 `AimIntent` 契约、炮镜刻度、测距与距离装定。测距和装定后续必须进入真实射击解，不能只改变 HUD 文本。

WT-008 的炮塔加减速、动态俯仰约束、车型稳定器能力及移动/急停射击差异仍待推进。当前炮镜 `look_at()` 使用世界向上方向，横滚呈现尚未按无稳定、单向或双向稳定能力区分；镜位随实际车体移动不能据此宣称完整无稳定光学已经实现。窄墙/棚顶侵入光学镜位的边界也需补充场景验证。

下一步继续两样车越障急停、建立瞄准、真实射击与战损恢复的体验链，并按完整路线补齐 WT-007/008；本批工程检查不能作为 WT-007 或整车手感的整体签收。
