## 已接入的行为

服务器在车辆完成发射与库存提交后、弹丸推进前的 priority 99 采集实际发射事实，弹丸的终止信号记录对应结束事实。`try_spawn` 的调用中不增加外部回调。每一发都有不可变的 `round_id / projectile_id / shooter_id / shooter_life_id / shot_id`；同一弹丸只能先发射、后结束一次。发射事实使用出生 tick，结束事实使用实际结束 tick。

服务器的 priority -100 回调只接收输入与确认。普通快照和新基线由独立的 `SimulationPhases.SNAPSHOT = 400` Publisher 在车辆、弹丸、比赛阶段后捕获。普通快照、同包本人状态和事件 head 因此对应同一个已完成物理步。结束请求先拒绝新输入、清理待执行命令；随后在本步 400 阶段关闭剩余弹丸并冻结终局，后续重发复用冻结的 tick、姿态、私有状态和原始 JSON 内容。

客户端只在整批事件通过结构、会话、连续序号、时间顺序和弹丸身份检查后提交游标及活动弹丸集合。快照中的 head 是服务器进度，不能代替客户端已经应用的 cursor。重复包不重复发出事件信号，畸形后缀也不能提前创建该包前面的弹丸。

短时断开保留本地公共事件检查点；重新连接同一服务器会话且历史仍在保存窗口内时，补发未确认的连续后缀。车辆控制仍重新分配并产生新 control epoch，事件恢复不保证找回原车辆或账号席位。

首次加入、服务器新会话及历史超窗均通过显式基线恢复当前状态。基线同时携带当前车辆快照、仅本人的火控/库存摘要、事件游标和当前在飞弹丸的身份、位置、速度、重力及飞行时间。迟到加入不播放加入前的发射特效，之后能用基线中的身份接受该弹的唯一结束事件。超窗情况显示 `history_evicted` 和跳过数量，不把缺失历史宣称为已连续补回。

跳过数量按“新基线 cursor − 接受前本地已应用 cursor”累计。`checkpoint.after` 仍验证服务器请求区间，但它只是服务器最后收到的 ACK，不能用于计算本地真正未见的事件数；已经应用、仅 ACK 丢失的尾部不会再次计为跳过。重复基线也不重复累计。

最终确认必须包含同一 session、已应用到终局 head 的事件游标及原始终局 JSON 的 SHA256。客户端在终止事件尚未补齐时显示“正在补齐终局事件”；仅有终局摘要不能提前完成。服务器保留未确认终局并重发，重复包不会重复触发完成信号。终局后新加入的 peer 被明确拒绝，不改变冻结快照中的控制状态。

## 结构及边界

| 内容 | v5 结构/规则 |
| --- | --- |
| 公共快照 | `version, session_id, sequence, tick, vehicles, event_sequence`，车辆最多两行；不再内嵌旧式 events 数组 |
| 事件 | `version, sequence, tick, kind, shot, payload`；kind 为 `projectile_fired / projectile_finished` |
| 发射 payload | `shell_id, position, velocity, gravity` |
| 结束 payload | `reason, position` |
| 连续批 | `version, session_id, after, head, events`；首条必须为 after+1，最大 16 条、24 KiB |
| 基线检查点 | `version, session_id, cursor, after, reason, active_projectiles`；与同包快照 head、session 一致 |
| 单个当前弹丸 | `shot, shell_id, position, velocity, gravity, age_s`；来自实时 ProjectileState，不能拿旧发射原点冒充当前位置 |
| 事件 ACK | `session_id, cursor`；不得回退、确认未发送事件或跨会话 |
| 基线 ACK | `session_id, cursor, snapshot_sequence`；精确匹配服务器正在等待的基线 |
| 最终 ACK | `session_id, cursor, digest`；cursor 同时等于该 peer 已确认游标与终局 head |

会话 ID 是服务器每次启动生成的 32 位小写十六进制标识。整数须有限、无小数且在 JSON 安全整数范围内；标识、坐标、速度、重力、年龄和字节数有明确上限。额外字段、布尔数值伪装、非有限量、重复身份、非法发射/终止次序均被拒绝。

事件日志最多保存 256 条；活动弹丸最多 64 发，射手身份水位最多 64 项，客户端近期事件也最多 256 条。请求早于最旧可补发位置时只返回明确 resync，不构造伪连续批。所有数据仍只在现有 127.0.0.1 / 两个 ENet peer 边界内运行，公共事件没有完整内部毁伤、敌方私有测距或奖励声明。
