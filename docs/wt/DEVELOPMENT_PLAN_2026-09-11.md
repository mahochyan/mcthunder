现有项目已经不是空框架，而是覆盖若干关键功能的陆战原型。距离目标的核心差距是：驾驶与火控的深度、可解释的复杂毁伤、观察与战场战术、完整比赛与可信联网，以及能稳定量产的内容。继续只增加车型、按钮、测试断言数量，不能证明正在接近“战争雷霆式玩法”。应保留已有状态、命令、事件、弹药和模块基础，以真实对局的体验门槛重排后续开发。

## 2. 产品目标与范围

最终方向：原创低模视觉、战雷式载具战术、完整中文交互、可以和真人持续对抗的陆战产品。建议以“陆战拟真取向”作为主规则，训练/辅助预设另行配置。官方陆战拟真参照强调观察、出击资源与编成，且包含空地联合；不应把旧离线4v4认作最终目标。[W01]

### 三个不可混淆的层级

**核心完成样片**：两辆完成样车、一张能体现观察/掩体/机动的地图，驾驶、火控、毁伤与恢复可理解；并有独立服务器两客户端技术切片。

**完整陆战产品**：离线与联网闭环，先4v4再验证8v8；建议首发窄年代车池约8—12辆、两个能组成实用编成的阵营、三类地图，完整车库/研究/配弹/训练/对局/保存/设置/结算/房间。数字是规划目标，不是现状或对原游戏内容量的等量承诺。

**现代与空海扩展**：用户关注M1A1/99A，因此现代能力样车在通用核心成熟后即进入并行主线，不等大量二战车量产。现代首发需过现代对抗门；空地、防空、直升机、独立空战与海战属于后续独立模式包，全部登记，不假装已经由陆战原型覆盖。

旧036定义的是离线4v4、四车两图、训练挑战和轻量进度的独立首版。保留其历史与已实现成果，但它只是内部原型里程碑。[R03]

“复刻玩法”的验收采用可观察行为和战术选择，不声称拿到或完全还原未公开内部公式。公共史料、自己的游戏抽象、原游戏行为参照分栏记录。

## 3. 先把哪些体验做出来

### 驾驶必须影响战术

先让质量感、刹停距离、倒车能力、坡上动力、转向损速和接地表现成立。相机点头不能替代车辆动力，履带滚动贴图不能替代左右履带状态。自定义可控运动方案可以继续演进；Godot官方也提醒VehicleBody3D并非开箱即用的高真实性车辆方案，因此不把换节点或换引擎当完成路线。[R04][W05]

### 火控必须决定“什么时候能开好这一炮”

视线、瞄准意图和炮管指向独立；望远镜观察、测距、装定、不同光学倍率、有限俯仰、炮塔加减速和稳定器必须组合起来。官方稳定器说明区分单向/双向能力，也说明视线稳定时炮管仍可能未对齐；我们的规则需要真实地表达这种区别，而不是给所有车辆加同一个防抖开关。[W02]

### 毁伤必须改变下一步决定

同样是“命中”，穿透、跳弹、击伤炮闩、击断履带、损失乘员、击中实际有弹的弹架应产生不同后果。现有无整车总血条方向应保留。引信、破片、内部遮挡与恢复系统统一围绕实际ShotRecord，不允许回放另算一套更好看的结果。[R06][R08]

体积弹丸的必要性是避免把炮弹当无尺寸点穿过细缝。原游戏2020年的开发日志介绍过多射线表征截面的方案；可借鉴其问题定义，不照抄未公开实现，也要独立防止接缝重复抗性与薄层丢失。[W03]

### 对局必须奖励观察、路线和编成

一张地图至少有近战、主线、绕侧和远射的不同空间；不同路线有暴露风险和反制，出生不能被安全位置包办。AI围绕有限情报做决策，烟幕和声音不是只给玩家看的装饰。出击点数、剩余编成、占点与支援把一连串交火变成有战略后果的一局。

## 4. 技术演进方案

保留Godot/GDScript和现有项目，以小提交渐进替换。建议结构如下；名称为拟新增/拟重构职责，不表示现在全部存在。

```text
输入来源：LocalController / AIController / NetworkController
    -> VehicleCommand（带序号、所属实体和输入时刻）
    -> MatchSession / BattleWorld（唯一权威模拟）
         -> VehicleDynamics
         -> TurretAndFireControl
         -> WeaponAndInventory
         -> Projectile / Armor / InternalDamage
         -> Capabilities / Recovery
         -> Objectives / Spawn / Result
    -> 已提交的状态快照与事件
         -> 本地画面 / HUD / 音频 / 回放
         -> 网络可见性过滤后的消息
```

一个物理步的逻辑顺序要写清：验证并消费命令→推进车辆/机构/装填状态→发射→推进弹丸和接触→提交毁伤/能力→比赛事件→快照发布。具体引擎回调实现应通过测试确认，不能仅靠文档箭头假定已有严格顺序。

网络接口从M0建立，WT-009早做两客户端技术切片。正式联机采用服务器裁定，客户端提交意图；快照、预测与纠正解决操作延迟。不要让客户端上报“我击毁谁了”，也不要只同步坐标后让各端自行结算。Godot官方提供ENet等基础并明确建议权威状态、RPC验证和速率限制；这些API不会替我们自动完成安全设计。[W04]

有限弹速的网络武器要有统一时间基准和有限补偿策略；不能无条件把任意历史客户端瞄点当真。在线研究/收益不能直接相信当前离线JSON。比赛结果、重连、重发均用唯一身份与幂等收据处理。

从TeamRange渐进抽取通用战场与比赛控制器，把训练关、挑战、离线队战、服务器都放在同一战斗底座。对get_children扫描、全量快照重建先采样再优化；不把源码行数当作性能证据。[R11]

## 6. 现代车和资产的明确策略

先用既有四车与标准夹具验证通用系统，不因新增M1A1就废弃旧工作；同时把M1A1确切改型作为现代能力样车。99A等进入同一资料/资产规范，先证明系统支持，再冻结正式车池。自动装填、热像、复合甲、反应甲、告警、雷达和主动防护均按车型分配，不把“现代”当作全部功能都具备。

原游戏2024年公开改动把自动装填、火控、供电等做成有功能后果的模块，这说明现代玩法差距不只是弹速和贴图。[W06]

低模模型的四层数据应分离：可见网格、移动碰撞、装甲几何、内部模块/人员。轴心、炮口、光学挂点和坐标规范共享；轮廓不能与实际命中结构明显背离。细节能烘焙，但炮口/炮塔几何与运动轴不能烘焙替代。每次重导入自动检查尺寸、朝向、LOD、挂点和碰撞。

当前约1k模型与M1A1文档高面数档位先做对比试验，不把100k+当自动合理，也不把严格1k当low-poly的唯一标准。预算依据目标硬件、屏幕占比、8/16车场景和材质成本决定。[R02][R16]

项目入库政策建议：只收原创或经许可核对可用于目标发行方式的资产。网络参考图、烘焙源、可再分发模型分开登记；只有“我拿到了文件”不算完成来源核验。此处是项目验收规则，不作特定素材的法律结论。

## 7. 验收制度：别再用断言数量当完成度

每项至少记录：玩家新增能做什么、实际改动、被测SHA、真实运行命令/退出码、工程通过范围、图形/音频证据、真人原话、未验证项。长套件中途停止只能写部分观察，不能升格成全套通过。

关键门集中在核心样片、完整对局、现代对抗和发布候选；不要求每个小提交都等真人回复，但依赖手感选择的工作不能在未定案时大规模复制。发现阻断问题先修；不依赖它的资料整理、工具与资产规范可继续。

推荐完整场景：坡顶急停瞄准；绕侧后选择内部部位；受损失能后用烟幕/维修/支援应对；抢点后撤退与换车；多人环境同一炮和同一建筑缺口状态一致。都从正常入口用正常输入完成，开发作弊夹具仅用于另行标记的边界测试。

建议体验调查分为新玩家与战雷熟悉玩家，不把一次喜欢/不喜欢当统计结论。记录首局不理解的步骤、命中结果解释、最严重的操作阻力、战术选择和是否愿意主动再开一局。把人的观察与自动遥测对照，而不是用某个留存百分比提前宣称成功。

**交付**

**验收**

- 暂停、重生、换车后不补发旧输入
- 不把同一版本受控回归等同于跨平台浮点确定性保证

- 独立服务器构建和多人客户端构建
- 可靠生命周期/结果通道与有序快照通道
- 4v4 全局一致性与场景切换测试

**验收**
- 不能只同步坦克位置而由各端独立裁定毁伤
- 死亡、弹药、建筑缺口在各端对应同一权威状态
- 观战、重连和复活不会收到错误生命周期的数据

## WT-025｜预测、插值与延迟下的射击

阶段：M4。职责：网络/核心程序。依赖：WT-024, WT-010。

本地控制预测与服务器纠正、远端插值、有限历史快照和时间戳验证。有限弹速武器采用明确的延迟政策，不能直接复制即时命中射线的无限回溯。

**交付**
- 网络时间轴和最大补偿窗口说明
- RTT/抖动/丢包可重复测试场景
- 纠正幅度、事件延迟和争议命中日志

**验收**
- 建议测试 RTT 50/100/150ms 与 1%/3% 丢包，结果逐档报告而非一概宣称流畅
- 客户端伪造旧时间戳不能获得额外命中优势
- 炮弹与移动目标使用一致时间基准；视觉命中不覆盖服务器结果

## WT-026｜联网权限、身份与进度安全

**验收**

## WT-027｜M1A1现代能力样车
