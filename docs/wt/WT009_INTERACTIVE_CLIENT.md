# WT-009 可操作客户端与重新连接

开发基线e8edf4f。新增NetworkBattleClient、NetworkClientView和client_main入口，使用已有独立本机服务器。玩家可以键盘驾驶、鼠标瞄准/射击、炮镜和自由观察；画面中的车辆姿态来自服务器快照，客户端副本不执行驾驶、炮塔机构、装填或开火结算。

## 试玩

先启动根目录`START_LOCAL_SERVER.bat`，再启动`START_LOCAL_CLIENT.bat`；可打开两个客户端窗口，各控制服务器分配的一辆车。仅连接127.0.0.1:19109。W/S驾驶、A/D转向、鼠标瞄准、左键射击、右键炮镜、B自由观察；Esc释放鼠标并清空输入，Enter恢复，R重新握手。

当前为平坦训练场。R会申请当时可用席位，不保证找回此前车辆/账号/比赛；不是会话恢复。两辆车的完整车库、出击和占点比赛尚未接入。

## 实现边界

客户端复用PlayerController生成命令，将观察点转换成显式世界瞄点再发送。20Hz发送间隔使用CommandMailbox保留短促开火边沿；积压超过200ms后清空，断开、失焦、Esc及重新连接也清空并要求释放火键。服务端继续校验输入身份/控制纪元/序号/tick期限。

NetworkBattleClient独立管理ENet连接、版本握手、服务器快照和终局确认，连接超时显示断开。车辆外观由真实车型资源构造，物理驾驶回调关闭；无本地ProjectileManager。服务器只向对应控制者另发弹药余量、装填时间与速度，未将这些字段放进双方共同的事件快照。最终结果文字读取服务器事件。

客户端现已使用下文记录的姿态插值，尚无本地预测；炮弹飞行/闪光/命中视听尚未接入客户端。下行协议校验和恢复机制仍需加强，公网身份、房间、完整弹药/模块毁伤同步、重生与可恢复快照没有完成。

## 实际验证

`tests/run_network_view.ps1`启动独立服务器与真实1280×720客户端窗口；窗口内第二个网络peer仅用于验证独立分配，不把它冒称第二个窗口进程。最终证据`logs/wt009-view/20260911-135106`记录命令、源码基线、被测文件/引擎SHA256、两进程退出码0和实际截图，stderr为空，10项通过：

- 服务器分配车辆、第二peer分配不同车辆。
- 真实Input动作驱动PlayerController，经网络往返后车辆移动超过0.5m。
- 实际鼠标按下/释放产生一次服务器发射，并收到弹药与装填状态。
- 客户端副本驾驶调用数和发射计数始终为0。
- 真正保存窗口截图，已目视文字与车辆显示。
- 断开后通过R键重新握手，服务器控制纪元增加、恢复输入且无旧开火边沿。

另运行`tests/run_network_slice.ps1`，`logs/wt009/20260911-134943`三个独立进程退出0、完整终局摘要一致，验证新增私有状态消息未破坏原命令/事件路径。首次8项和中间9项窗口记录另保留，不冒称最终源码全量测试。

这些是程序注入输入的实际窗口/网络检查，不是玩家手感验收，也不是多人完整比赛验收。下一步应深化驾驶火控，同时补弹道呈现、受控断线恢复及完整毁伤下行。

## 2026-09-11 姿态插值补丁

开发基线1f456ae，实际被测文件哈希见各证据RESULTS。NetworkPoseBuffer在客户端保存最多32份权威姿态，采用6个60Hz物理tick（约100ms）显示延迟。渲染帧插值位置及最短弧角度，先更新车辆再更新相机；包中断时停在最后姿态，不外推。当前本车同样经过该延迟，没有本地预测，不能据此声称驾驶延迟已解决。

同一实体的life/generation/control_epoch变化时直接使用新姿态，不穿过旧生命周期路径。晚到/重复序号与非有限坐标被拒绝；同tick但更高序号的最终快照替换最后状态，最终显示跳到终局tick。真正断线与R重连清空缓冲；终局清空操作。事件文字现在在同一次快照更新HUD，消除上一版的一包滞后。
