# 河谷枢纽 — 10v10 / 16v16 大地图设计

2026-09-13；用户最新决定：**最多三个占点**。该决定覆盖此前五点/七点草案。两种人数均只设 A 采石场、B 货运站、C 河畔镇。其他地标没有占领计分。

本文件交付原创布局、环境方向、可运行勘察样板及后续验收标准。当前不是已接入 20 / 32 玩家战斗的正式地图，也不宣称已经达到 BattleBit 的完整美术质量。所有尺寸、战斗距离和计分参数均为本项目设计值。

后续增量已加入真实单车驾驶、两种活动布局、桥台/护栏/屋顶/树干碰撞和39处防御土工结构，见 `WT032_RIVER_DRIVING.md`。下方“当前样板状态”和2735棵树等为2724b27a设计样板的历史快照；当前生成树木2654棵，实战、团队和最终美术验收仍待完成。

## 进入与操作

启动游戏 → 车库 → 训练中心 → **河谷枢纽 · 大地图勘察**。可切换 10v10 / 16v16 布局、点击战术图和地标定位、查看街道尺度；按住右键观察，WASD 移动，Q/E 升降，Shift 加速，Esc 返回。勘察不改阵容、进度和奖励。

也可以直接运行 `scenes/maps/river_junction_survey.tscn`。正式地图注册表仍只包含此前两张战斗地图，避免把预览误当可玩 16v16 对局。

## 参考与取舍

BattleBit 官方大型地图开发日志介绍了按人数另设布局、增加绕行通路、缩短空旷转场和组织不同距离交战区的做法。本设计采用“同一地形、两种活动边界”和分散河道通路；考虑到本游戏主要驾驶坦克，避免单桥承载全部推进压力。这是我们对官方设计说明的应用，不复制其地图形状或资产。[官方大型地图开发日志](https://steamcommunity.com/app/671860/announcements/)

BattleBit 官方视觉改造说明强调景深层次、阴影和远处环境的可读性。本图以这些视觉目标为参考，保留 Godot Compatibility 渲染器；官方文章描述的是改造方向，不等于本项目已具备相同技术或画质。[官方视觉改造说明](https://joinbattlebit.com/visual-changes-overhaul/)

## 地图规格与三条主战线

背景：虚构中欧温带河谷，河流横贯东西，铁路货场与沿河小镇组成交通枢纽。苏德地面车辆优先；不绑定真实地点或某一历史战役。

| 项目 | 10v10 | 16v16 |
|---|---|---|
| 整体地形 | 2.4 × 2.0 km | 同一地形 |
| 活动区 | 1.48 × 1.20 km | 2.08 × 1.60 km |
| 同时计分占点 | A / B / C，最多 3 个 | 同样 A / B / C，最多 3 个 |
| 跨河道路 | 西、中、东 3 处 | 增加两翼绕行，共 5 处 |
| 每方初始泊位 | 10 | 16 |
| 基础出生纵深 | z = ±480 m | z = ±680 m |
| 两处部署场中心 | x = ±260 m | 同左 |
| 外围木材场/中继站 | 活动区外，不计分 | 侧翼地标，不计分 |

活动区使用矩形边界，边缘还有地形背景；正式战斗边界限制、越界提示与复位尚待接入。较少人数不增加抢点任务；较多人数增加可利用的侧翼宽度和集结空间。

| 占点 | 样板坐标 x/z（m） | 设计角色 | 后续占领区与入口 |
|---|---|---|---|
| A 采石场 | -520 / 120 | 西线起伏、石料堆与反斜面；适合机动包抄 | 40 m 半径初值；坡道、沿河路、场后出口 |
| B 中央货运站 | 0 / -130 | 中线货棚、装卸平台、车皮和交叉巷道 | 35 m 半径初值；货棚两侧和南北货运通道 |
| C 河畔镇 | 520 / 100 | 东线街角与院落；接近后仍能绕至侧面 | 35 m 半径初值；主街、两条横街、外围环路 |

机修厂、农庄、木材场、中继站作为非计分地标，帮助玩家辨认位置、隐蔽转移和绕过堵塞。不得在后续实现时自动把它们转成第四个占点。

三个占点分布不是最终公平性认证：目前 A/C 在南岸、B 在北岸，双方首达路线不对称。下一批需要以真实坦克路线用时调整部署出口、掩体或占领区，不能仅用直线距离宣称平衡。

## 交战、转场与出生保护目标

以下为待实测的关卡验收目标，并非本轮测试结果：

| 指标 | 目标 |
|---|---|
| 城镇主要交战距离 | 60–180 m；不让一条主街贯通整个活动区 |
| 货场主要交战距离 | 120–350 m；车皮间留侧穿和后退空间 |
| 丘陵主要交战距离 | 250–650 m；少量远射位置，不允许一个高地控制三点 |
| 关键进攻路线的硬掩体间隔 | 60–120 m；连续暴露段原则上不超过 180 m |
| 主路宽度 | 15 m 可驶车道，21 m 路肩；桥面 23 m |
| 侧路与院落开口 | 不少于 10 / 14 m；关键会车处能绕过一台损毁坦克 |
| 出生泊位净间距 | 18 m；两处部署场；每处至少两个方向出口 |
| 第一次有效交战 | 10v10 约 45–80 s，16v16 约 60–100 s；按实际车辆测量 |
| 相邻占点安全转场 | 目标 45–90 s；越野捷径更快但更暴露 |
| 双方首达时间差 | 同等驾驶条件下争取 ≤15%；分别核对三点，不只比较均值 |
| 出生保护 | 可控部署区之外不得直接看见出生泊位；用土堤/建筑实遮挡，不靠树叶或雾 |
| 坡度 | 主路持续坡度 ≤8%，关键越野入口 ≤18%；独立检查长车底盘与炮管净空 |

目前道路骨架提供多通路，但硬掩体和出生屏障密度尚不足。战略图断一路仍连通，不代表真实驾驶、射线遮挡或残骸交通已经验收。下一步先补这些功能结构，再扩大装饰密度。

占领规则草案：三个点等权，双方进入同一区域时争夺暂停；无人区不自动翻转；两点多数触发敌方票数衰减。占领速度按参与车辆数封顶，防止 16 人堆单点瞬间翻盘。具体计时、票数和重生规则复用主线比赛规则，另行实现并测试；本轮没有新增计分器。

## 环境美术标准

用户要求环境至少向 BattleBit 的完成度看齐，覆盖旧的“所有场景必须极简低模”理解；车辆现有低多边形方向继续保留。环境以比例、结构、材质层次和战场可读性为准，不为追求低面数删掉必要形体。

| 层次 | 制作要求 | 当前样板状态 |
|---|---|---|
| 大地形 | 河岸、谷地、外沿山体、道路整形；近景平滑过渡 | 已有分块地形、河槽、道路/部署场整形；仍需局部人工修形 |
| 建筑轮廓 | 屋顶、山墙、烟囱、基础、檐沟；不同功能建筑应有独特轮廓 | 34 个建筑壳体；货棚与民居有尺度区别，外侧地标仍重复 |
| 近景立面 | 窗框、窗台、百叶、门阶、砖/灰泥细节；不是单色箱体 | 已有几何附件和程序砖缝；缺破损、招牌与多套材质变体 |
| 植被 | 树冠层次、树干/枝干、灌木/地被分层；森林与田地有清楚边界 | 已有 2735 棵批量树木与圆滑树冠；叶片细节、树种变化和地被待做 |
| 道路与工业 | 路肩、标线、路缘、桥墩护栏、道砟枕木、装卸设备 | 已有首轮结构；磨损、车辙、电线、碎石与工业专用资产待做 |
| 视觉深度 | 自然天光、适量空气透视、近远一致的掩体轮廓 | 已接入，截图已审；远景替代层与各设置档公平性未验收 |
| 破坏状态 | 关键硬掩体定义完整/破损/残骸碰撞，装饰破坏不阻断唯一路线 | 未实现；本轮建筑为封闭壳体，树木和多数小道具没有战斗碰撞 |

目前是环境方向样板，仍明显低于最终 BattleBit 级别的资产丰富度与打磨程度，不能把平滑球状树冠或增加网格数量单独当作画质完成。优先完成河畔镇一个可近看街区的最终资产，再替换其他地标；不一次铺满重复民居。

Godot Compatibility 技术预算设计：地形和树群以 200 m 单元组织，环境材质复用；后续为建筑/植被提供 LOD 与远景替代，保留影响射击判断的遮挡。该组织方式属于新地图实现基础，不代表性能专项已恢复。20 / 32 车辆完整对局、长时间残骸堆积及网络性能测试继续等待对应主线阶段/性能授权。

## 已实现与后续接入

数据：`scripts/maps/river_junction_definition.gd`，包含两个人数配置、强制三点上限、部署泊位、地形函数、跨河道路与战略节点图。

环境：`scripts/maps/river_junction_world.gd` 与 `assets/shaders/river_*.gdshader`，包含原创程序环境；无外部模型或网络图片资产依赖。

入口：`scripts/ui/river_junction_survey.gd` / `river_junction_atlas.gd`，接入原车库训练中心。

按依赖继续：

1. 三占点功能布局：真实占领区、出生遮挡、硬掩体、可撤退路线、坡度与桥头通行；采用已有四车先核对真实驾驶。
2. 大图导航：现有 `DriveNavigator` 最多 256 节点、起点要靠近局部节点；本图战略节点图不直接灌入现有驾驶器。先加区域层与局部接驳，再验证断桥/残骸绕行。
3. 比赛容量：现有 `TeamRange` / `TeamArena` 仍有固定阵容和目标索引。先改可配置团队规模/目标分配，再接入三个占点的权威规则；不能只改人数标签。
4. 环境精修：河畔镇 → 货运站 → 采石场 → 非计分地标；人工布置地被、硬掩体和轮廓独特资产，加入明确碰撞/破坏分类。
5. 实战验证：真实 10v10，再 16v16；换边、不同车型、拥堵/救援/补给/残骸、重连与完整结算。画质审查、真人体验、性能与发布门独立记录。
