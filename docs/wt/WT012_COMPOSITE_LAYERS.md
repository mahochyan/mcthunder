# WT-012 被动复合装甲与实际附加层

开发基线 `6b12e42b38c94b72b864a871bf22a3bb96611a9b`。42项要求全部保留；WT-012/013/027/030继续进行中。性能HOLD_BY_USER、真人NOT_RUN、release_ready=false。本批是明确游戏设计的被动材料/几何能力，不是苏德真实防护数据或完整整车交付。

## 生产路径

ArmorPatchDefinition新增可选response_profile，composite必须显式配置wt012-passive-composite-v1、game_rule说明和kinetic/chemical/fragment三种正数系数。rolled/cast沿用原弹药侧规则；未知材料或厚度不借用复合规则。无显式弹药响应的旧弹遇到composite返回unknown_material，不能偷偷当作钢板。

物理thickness_mm与游戏抗力分开：AP/APHE与破片的复合抗力使用实际LOS×独立通道系数，禁止套用钢板法线化/炮口口径碾压；APFSDS沿用已配置的独立角度曲线×动能系数。HEAT使用LOS×化学系数且不跳弹。几何厚度仍供原引信/路径规则读取。版本和通道写入实际装甲接触事件。

VehicleContentPipeline支持显式armor_layers，最多32块有限凸四边形，每块包含唯一id、hull/turret/barrel挂接、局部米制vertices_m、单位normal、物理thickness_mm、material、可选response_profile与reason。独立表面坐标决定接触顺序和两个接触面的距离；数组顺序不能决定穿透次序。原装甲未知记录仍保留。层位置用真实表面坐标表达，尚非完整有限体积弹丸/材料实体模型，不能把接触面间距冒称扣除材料厚度后的净空气间隙。

新增层逐条要求facts[protection.layer.<id>]与完整条目精确相等，structured单位、game_rule/estimated来源和字段定位；已有装甲区改为复合材料则要求独立facts[protection.zone.<zone>]。源身份/哈希/读取状态继续经过参考准入门。附加层进入既有LayoutValidator的几何、唯一ID、实际部件及边界校验；有限片的周界独立登记。它们不是替代未声明车体缺口的豁免。

运行时查询、HEAT射流、直接弹道和长杆破片读取同一面片的深复制规则。旧VehicleAtlas本来就渲染全部查询面片；显式GLB路径补装附加层的实际网格，并挂在真实车体/炮塔/炮管节点，源模型米/厘米缩放不再次作用于米制装甲层。补充层为工程内显式游戏几何，不修改外部制作中的模型。

## 回放与验证

冻结几何保存每块面片的response_profile，接触记录核对其精确一致性、版本、通道、材料系数和重新计算的抗力/剩余预算；复合命中点必须落在冻结面的实际有限三角形中，不能把面片移到别处仍通过。已冻结事件不受后来修改布局中的嵌套系数影响。这是记录内部一致性门，不是密码学真实性证明或完整物理重演。
