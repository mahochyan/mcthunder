# UI-BIZ-01 阶段4：1280x720 @125% 编成条的 5px 缺口（实测记录）

## 现象（可复现）
un_garage_frontend_checks.gd 在 1280x720 @125% 下 1 项失败：
  [FAIL] the selected vehicle card is scrolled into view: 1280x720@125%
  [selected card] rect=[P:(250.0, 611.0), S:(216.0, 114.0)]  strip=[P:(24.0, 611.0), S:(1232.0, 114.0)]
卡片底边 = 611 + 114 = 725 > 720 ⇒ 超 5px。
对照：1280x720@100% 余 53px；1920x1080@125% 余 58px。仅此一个组合不达标。

## 已排除的原因（各有实测）
1. 不是"标签里的百分号被当格式符"——report() 是字符串拼接，不做格式化。
2. 不是"引用失效"——审计诊断显示 root 已释放，守卫对已释放实例用 is 会抛错；已改为先 is_instance_valid。
3. 不是"外层边距不够"——实测：减少外边距腾出的 8px 被可扩展的中部（车体展示区）吸收，
   编成条 y 完全不变。条的位置 = 窗高 − 下边距 − 页脚高 − 条高 − 编队行高 − 间距。
4. 不是"主题变化钩子"——设置父节点 theme 不会把 NOTIFICATION_THEME_CHANGED 传给子节点（实测矩形逐字节相同）。

## 结论与下一步（唯一剩下的正确方向）
要移动/收窄这一组合，只能动**下边距**或**条/页脚高度**；而设计单把条限定 80-112，
125% 下卡片自身即需 114 ⇒ 二者不可兼得。下一轮二选一并出证据：
  (a) 125% 时下边距按紧凑值（16）而不仅是外边距——预期刚好补上 8px；
  (b) 或把此组合登记为 NOT_MET，附上述数字（不削弱任何断言）。
