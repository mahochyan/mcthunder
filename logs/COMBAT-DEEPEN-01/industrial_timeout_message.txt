WT-EXPANSION-02: the industrial suite's registered failure was unreachable through the gate because the gate's timeout was smaller than the suite's measured budget

run_industrial_battle_checks is registered as a pre-existing arrival red, but the gate could never accept it: the
register matcher refuses a registered failure whose run TIMED OUT, and the runner's shared 1500 s bound expired first.

MEASURED (logs/COMBAT-DEEPEN-01/industrial-budget.log, the suite run alone with NO timeout, --fixed-fps 60):
  wall     = 4327 s (~72 minutes)
  checks   = 16, failures = 1, SCRIPT ERROR = 0, ^ERROR: lines = 0
  failure  = "[FAIL] at least three actual slots from each team physically reach central approaches" - EXACTLY the
             registered signature, exactly once (seed 23023 passed that check, seed 23024 failed it)
  So the suite is a correct, healthy registered red; the only thing wrong was the bound it was given. It is CPU-bound
  rather than real-time bound: two seeds simulate about 710 s of match clock with 8 AI actors and full perception.

VERIFIED WITH THE GATE'S OWN MATCHER against that real failing line
(logs/COMBAT-DEEPEN-01/verify_industrial_register.ps1, dot-sourcing tests/candidate_register_match.ps1 and reading the
register out of build_release.ps1's AST):
  REAL_FAIL_ACCEPTED=True      the failure set matches the register exactly
  TIMEOUT_REFUSED=True         is a registered failure but its run timed out
  SCRIPT_ERROR_REFUSED=True    is a registered failure but its run also reported 1 unexpected script error(s)
  EXTRA_FAILURE_REFUSED=True   failed 2 check(s) but its registered signatures account for exactly 1

CHANGE (tests/run_suite_checks.ps1): the bound is now derived per suite - a $suiteTimeouts map gives
run_industrial_battle_checks 6000 s (a ~1.4x margin over the 4327 s measurement) while every other suite keeps the
shared 1500 s, so hang-detection latency everywhere else is unchanged. No check, criterion or expectation was touched.

VERIFIED: the runner parses with 0 errors and stays pure ASCII, and evaluating its own map from the AST selects
6000 s for run_industrial_battle_checks and 1500 s for run_checks / run_village_battle_checks. The end-to-end run of
that suite through the runner (which costs another ~72 minutes) is started and its RESULTS.json is the evidence for
the next round.
