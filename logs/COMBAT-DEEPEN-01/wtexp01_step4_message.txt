stops at the next real gate with the accounting proven correct.

WHAT WAS WIRED: try_fire_secondary now builds the launch spec in the same shape the main gun builds - round, shooter
identity and team, shot id, effect policy kinetic for an AP round, the round own declared impact profile, calibre,
seed, muzzle position and barrel direction, the round declared speed, gravity and bounded age and distance - and
calls projectile_manager.try_spawn. If the manager REFUSES the round, the belt debit and the cadence are ROLLED
BACK, so a refused shot never costs a round.

MEASURED, and the measurement corrected the code twice:

     and the difference between an accounted round and a flown one became visible;
  2. the manager refused the first attempt with invalid_armor_policy, and the cause was mine: the curve built from
     the packet pairs is an Array of Arrays, which PenetrationCurve.validate rejects outright, so the spec now
     converts the declared pairs into a TYPED curve before the launch;
  3. with that fixed the manager advanced to the next gate and refused with invalid_impact_profile, so the declared
     secondary profile does not yet satisfy the armour side complete-profile contract. The launch does NOT happen
     yet, and it is NOT claimed to: the measured answer is
     { "ok": false, "reason": "secondary_launch_refused:invalid_impact_profile" } with the belt UNCHANGED at 750 and
     200 and projectile_id 0.

WHAT THAT PROVES rather than merely asserts: the rollback is real. A refused secondary shot costs nothing - the belt
goes 750 to 750 and 200 to 200 - which is the property that matters when the gate is a real one, and it was measured
against the real manager rather than against the channel own bookkeeping.
